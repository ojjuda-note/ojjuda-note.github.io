# 앱 배포 없이 일반 아이템 등록하기

제작실에서 승인한 좌·정면·우 그림과 기준점을 등록하고 실행 자료를 내보낸다. 기존 원본 품질·접지·충돌·형태 승인 절차를 유지한다. 단순한 사진이나 미완성 작업 파일은 실행 자료로 대신하지 않는다.

1. 승인된 `.runtime.json` 파일과 작은 미리보기 PNG/WebP/JPG를 `house-test/assets/`에 올린다. 큰 자료는 파일 업로드로 전달한다.
2. 실행 자료의 SHA-256 앞 16자리를 구한다. 파일을 바꾼 경우 새 파일명을 권장한다. 미리보기만 바꿀 때도 새 미리보기 파일명을 쓴다. 파일 업로드가 완료된 뒤 목록을 게시한다.
3. `item-assets.json`의 `assets`에 아래 형식으로 추가한다. `schema: 1`과 기존 항목을 유지한다. 기존 내장 ID와 개인 제작 `made-` ID를 재사용하지 않는다.

```json
"item-new-table": {
  "file": "new-table-v1.runtime.json",
  "revision": "실제 SHA-256 앞 16자리",
  "catalog": {
    "label": "새 원목 테이블",
    "shortLabel": "새 테이블",
    "width": 2,
    "depth": 1.5,
    "height": 0.6,
    "layer": "standing",
    "preview": "assets/new-table-preview.png",
    "order": 1,
    "hidden": false
  }
}
```

크기와 `layer`는 실행 자료와 정확히 같아야 한다. `standing`은 가구, `floor`와 `surface`는 소품 메뉴에 나온다. 바닥·상판 높이와 세 방향의 초기 위치는 검증된 실행 자료에서 읽는다. `order`는 가구 메뉴의 새 아이템 순서다.

`item-` 뒤에는 영문 소문자·숫자·하이픈을 쓰고 첫 문자는 영문/숫자로 한다. 뒤쪽 식별자는 최대 64자다. 이름은 최대 80자, 전체 목록은 최대 2,000종이다. 그림은 목록을 표시할 때 모두 내려받지 않는다. 기존 방 한 개의 아이템 수 제한은 별도로 유지한다.

방을 닫았다 다시 열면 최신 목록이 반영된다. 기존 방에는 자동 설치하지 않는다. 같은 앱 주소와 버전으로 등록·수정되며 원본 파일과 목록만 게시하면 된다.

판매/목록 노출을 중단하려면 항목을 삭제하지 말고 `hidden: true`로 바꾼다. 그림과 실행 자료를 보존해야 이미 설치한 방을 계속 복원할 수 있다. 크기·층·충돌 공간이 달라지는 변경은 새 ID로 등록한다. 목록 오류·자료 손상·누락 때 저장된 배치를 삭제해서 복구하지 않는다.

기존 소파의 전용 쿠션/담요 부착, 책상-의자 연동, 벽 액자 등 특수 동작은 이 일반 등록 형식에 포함되지 않는다. 특별 동작이 필요한 아이템은 해당 기능을 먼저 지원해야 한다. 일반 소파 그림 자체는 세 방향 실행 자료로 등록할 수 있다.
