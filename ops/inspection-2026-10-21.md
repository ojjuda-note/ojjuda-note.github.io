# 2026-10-21 전체 기능 점검

기준 운영 커밋: `e2ca4cc48f80acd25b952060a1edbdd1e9e84f94` (0.46.20-beta). 수정 버전: 0.46.21-beta.

## 확인한 문제와 수정

- 설정에 예전 `화면·알림`의 강조색·밝게/어둡게 선택이 남아 있었다. 수동 화면 항목과 처리기를 제거하고 `알림`으로 정리했다. 계절·기념일은 한국 날짜 기준 자동 선택을 유지하며, 밝기 모드는 기기의 밝게/어둡게 설정을 따른다. 대문·월드·공원에 같은 동작을 적용한다. 과거에 저장한 수동 선택은 화면에 적용하지 않는다.
- 알림 갱신이 월드의 `설정`, `내 프로필과 설정` 버튼 이름을 모두 `메뉴`로 덮어썼다. 알림 갱신 시 각 버튼의 접근성 이름을 유지한다.
- DB 클라이언트 역할에 남아 있던 테이블 관리 권한(TRUNCATE, REFERENCES, TRIGGER, MAINTAIN)을 회수했다. 사용자 행 조작 권한과 컬럼별 권한, RLS, RPC는 유지한다. postgres 소유의 이후 마이그레이션 기본 권한도 정리했다. 운영 DB의 해당 클라이언트 권한 수는 181 → 0이며, anon/authenticated/service_role의 기존 CRUD 권한 해시는 전후 동일하다. 실제 사용자 행을 삭제하거나 변경하는 마이그레이션이 아니다.
- 사용 안내와 사이트맵의 설정 항목 설명을 현재 메뉴에 맞췄다.

## 범위와 남은 검토 항목

- 실제 Auth/Storage를 띄우는 전용 로컬 통합 검사 `account-deletion-local.test.cjs`는 이번 실행에서 제외했다. 계정 탈퇴의 기존 격리 모형 검사는 통과했다. 운영 DB로 백업을 복원하거나 실제 다중 사용자 부하 검사를 수행하지 않았다.
- Supabase의 공개 카드 뷰/SECURITY DEFINER 함수 경고는 계속 검토할 항목이다. 공개 카드 뷰의 작성자 식별자 제외와 숨김/차단 조건, 관리자 진입 검사, 쪽지·추천인 접근 제한을 확인했지만 모든 함수의 안전성을 보증하지 않는다. 경고 숫자를 줄이기 위한 일괄 권한 확대나 RLS 해제는 하지 않았다.
- 유출 비밀번호 차단 설정은 비활성으로 표시됐다. 연결된 도구에는 해당 Auth 설정을 변경하는 기능이 없어 변경하지 않았다.
- 약관·개인정보 문서에는 과거 방/카페/도서관/상점 등 중단된 기능 설명이 남아 있다. 현재 기능 안내는 수정했고, 법적 문서의 서비스·보관 설명은 별도 검토가 필요하다.
- Supabase 관리 역할(supabase_admin)의 기본 권한은 이번 마이그레이션의 소유 범위 밖이다. 향후 관리자 도구로 새 테이블을 만들 때에도 클라이언트 권한 검토가 필요하다.
