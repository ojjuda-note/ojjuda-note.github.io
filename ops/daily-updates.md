# 회원용 아지트 변경 알림

- 한국 시간 매일 밤 12시(00:00)에 회원 알림함에 게시한다. 당일 배포가 끝난 변경을 자정 전에 검증·준비해 두고 다음 자정에 공개한다. 날짜는 Asia/Seoul 기준이다.
- 최신 main에 병합되고 배포가 성공했으며 관련 검증이 완료된 사용자 기능만 포함한다. 배포 실패·보류·진행 중·되돌린 변경은 제외한다. 커밋 제목만 보고 완료로 판단하지 않는다.
- 관리자모드 전체, 원고실, 원고·만화 교체 및 내부 운영·백업·보안 기록은 제외한다. 관리자를 통해 일반 이용자 기능을 바꿨다면 일반 이용자에게 보이는 최종 결과만 포함한다.
- 중복 수정은 최종 결과 한 줄로 합친다. 한국어 한 줄 50자 이내, 보통 10~30자, 전체 1~3개 항목만 표시한다. 다정하고 자연스러운 말투로 쓰고 보고서식 표현·기술 용어·커밋 번호는 생략한다. 변경이 없으면 게시하거나 알리지 않는다.
- GitHub `ojjuda-note/ojjuda-note.github.io`의 변경 파일, PR, 관련 검사, 성공한 Pages 배포를 확인한다. `source_sha`는 해당 변경의 실제 커밋(40자리), `deployment_url`은 그 변경을 포함한 성공한 Pages workflow run URL이다. 해당 커밋이 배포된 커밋의 조상인지 확인한다. 같은 날 되돌린 기능은 포함하지 않는다.
- 게시 전 `ojjuda_updates_internal.daily_notices`에서 같은 날짜 존재 여부를 조회한다. 이미 게시했다면 재게시하지 않는다. 확인한 공지가 다시 나타나지 않도록 게시 내용은 불변으로 유지한다.

## 게시

Supabase 프로젝트: `ziezbdjofcugznowiuda`.
신뢰된 서버 작업에서만 아래 함수를 호출한다. 브라우저·일반 회원은 게시할 권한이 없다.

```sql
select ojjuda_updates_internal.publish_daily_notice(
  'YYYY-MM-DD'::date,
  '[{"text":"실제 확인한 변경을 한 줄로","category":"games","source_sha":"실제 40자리 커밋 SHA","deployment_url":"실제 성공한 GitHub Actions 실행 URL"}]'::jsonb
);
```

카테고리: `games`, `park`, `account`, `general`, `restaurants`, `festivals`.
예시의 자리표시자는 실제 검증값으로 바꾼다. JSON 문자열은 안전하게 인코딩한다.
게시 후 해당 날짜의 항목과 available_at을 다시 읽어 성공 여부를 확인한다. `available_at`은 보고일 다음날 00:00 KST로 고정된다. 자정 전에 검증·게시를 마쳐야 정각에 보인다. 늦게 처리된 예전 날짜 공지를 다시 게시하지 않는다.

## 알림함 표시와 확인

- `world.html`과 노트의 기존 종 모양 알림함(`note/notifications.js`)에서 표시한다. 별도 변경 팝업은 띄우지 않는다.
- 로그인한 모든 회원에게 동일한 내용이 보이며, `auth.uid()`로 각자의 읽음 기록을 서버에 따로 보관한다. 비회원에게는 회원 알림이 표시되지 않는다.
- 자정 공개 후 다음 자정까지 24시간만 새 변경 알림으로 유효하며, 읽은 공지는 알림함에서 읽음으로 바뀐다.
- 기존 알림의 빨간 점·읽지 않은 수·개별 읽음·모두 읽음 기능을 그대로 이용한다. 공지 내용은 텍스트만 표시한다.
- 한 번 보내는 월간 요약은 `ojjuda_updates_internal.broadcast_notices`에 고유한 ID로 등록한다. 전 회원에게 즉시 표시하고 30일 뒤 만료한다. 관리자·원고실 수정은 제외한다.
- 휴대폰 운영체제의 백그라운드 푸시와는 다르며, 앱을 열면 종 모양 알림함에 나타나는 방식이다.
