# 오쭈다 노트 내일 글 10개 준비

매일 한국 시간 밤에 실행한다. Supabase 프로젝트 `ziezbdjofcugznowiuda`에서 내일의 `ojjuda_note_internal.auto_card_copy` 대기열과 최근 14일의 본문을 먼저 읽는다. 이미 내일 분량 10개가 있거나 내일 일정이 만들어졌다면 새로 쓰지 않는다.

내일 올릴 한국어 카드 글 10개를 매일 새로 쓴다. 각 글은 90~170자 안팎, 200자 이내. 구체적인 장면 하나에서 시작해 감정이 조금 움직이는 흐름으로 쓰고, 결말은 훈계나 뻔한 격언 대신 여운 있게 마무리한다. 10개는 장소·감정·문장 시작과 리듬을 서로 다르게 한다. 최근 14일 본문과 같은 문장이나 비슷한 구조를 반복하지 않는다. 계절에 맞지 않는 날씨 묘사, 특정 지역을 직접 방문했다는 주장, 실제 이용자의 경험인 듯한 설정, 실존 인물, 광고, 정치, 19금, 사실 확인이 필요한 주장과 해시태그는 넣지 않는다. 독자를 속일 실제 제보나 경험담을 꾸미지 않는다.

작성한 10개를 검토해 맞춤법·중복·금칙어·길이를 확인한다. 그다음 전용 서버 측 Supabase 연결로 다음 SQL의 배열에 10개를 넣어 **내일 날짜로만** 대기시킨다. API 비밀키를 브라우저나 글 내용에 넣지 않는다.

```sql
SELECT ojjuda_note_internal.stage_auto_cards(
  ((now() AT TIME ZONE 'Asia/Seoul')::date+1),
  ARRAY['본문1', '본문2', '본문3', '본문4', '본문5',
        '본문6', '본문7', '본문8', '본문9', '본문10']::text[],
  'curated_automation'
);
```

SQL 문자열을 직접 이어 붙이지 않고 연결 도구의 구조화된 파라미터를 사용한다. 도구가 매개변수를 지원하지 않으면 작은따옴표를 SQL 규칙대로 이스케이프하고, 실행 전 내일 날짜와 10개 본문을 점검한다. 대기 후 `SELECT count(*) FROM ojjuda_note_internal.auto_card_copy WHERE local_day=((now() AT TIME ZONE 'Asia/Seoul')::date+1) AND ready_at IS NOT NULL`로 **10개인지 확인**한다. 실패 시 같은 글을 무한 재시도하지 않고 원인을 보고한다. 계정 활성화·크론 설치·게시를 이 자동화에서 직접 하지 않는다.

실행 시간 예: 매일 22:30 Asia/Seoul, 다음 날 08:00 이전 준비 완료.
