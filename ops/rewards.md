# 선물 보상 운영

## 적용 기준

- 배포 이후 추천인을 입력하고 가입 인증을 마친 회원부터 집계한다. 이전 방문 기록은 소급 추정하지 않는다.
- 가입 후 14일이 지나고, 가입일을 포함한 첫 14개 한국 날짜 중 7일 이상 이용해야 인정한다. 출석, 접속 시각 갱신, 게임 점수 등록을 서버에서 하루 한 번만 센다.
- 추천인별 인정 회원 10명마다 편의점 5,000원권을 반복 배정한다. 남은 인원은 다음 묶음에 합산한다.
- 전체 인정 회원은 500명까지이며 추천 보상 예산은 최대 250,000원이다. 월말 게임 보상은 이 한도에 포함하지 않는다.
- 동일한 휴대전화는 한 번만 인정한다. 자기 추천, 관리자 계정, 지정 제외 번호, 이용 제한 및 인증 미완료 계정은 제외한다.
- 한국 시간 매월 말일 23:59에 기존 순위표의 각 게임·난이도 항목 1위를 저장한다. 각 항목의 상품권은 5,000원이다. 동점 처리는 기존 순위표와 같다. 관리자나 손님이 1위인 항목은 지급하지 않으며 차순위로 넘기지 않는다.

## 월말 기프티콘 쪽지 발송

월말 확정 보상은 `awaiting_coupon`으로 보관한다. 관리자가 직접 구매한 기프티콘을 등록하면 기존 쪽지 알림으로 발송한다. 자동 구매나 문자 발송은 하지 않는다.

1. 관리자 → 추천인 → 선물 지급 관리(`/admin/rewards.html`)로 이동한다.
2. 월말 마감으로 확정된 당첨 건을 선택한다. 같은 사람이 여러 항목에서 1위인 경우 항목마다 별도 지급 건이다.
3. 구매한 상품의 이름, 바코드 아래 쿠폰번호, 사용기한, 선명한 기프티콘 이미지(PNG·JPG·WEBP, 5MB 이하)를 등록한다.
4. **이 당첨자에게 쪽지 보내기**를 누른다. 당첨자는 쪽지의 **기프티콘 열기**에서 이미지를 확인하고 저장할 수 있다.

수신자는 서버가 확정 지급 건에서 읽으며 닉네임으로 찾거나 임의 변경하지 않는다. 실제 로그인한 관리자 계정이 발신자로 표시된다. 친구 관계가 없어도 당첨 쪽지는 열 수 있지만, 어느 한쪽이 차단한 상태에서는 발송하지 않는다. 관리자 계정·지정 제외 번호와 수신자의 현재 자격을 발송 직전에 다시 확인한다.

비공개 `reward-coupons` 보관함은 당첨 계정과 관리자만 로그인해서 읽을 수 있다. 공개 링크나 서명 URL을 만들지 않는다. 쪽지에는 원본 이미지 주소나 쿠폰번호를 쓰지 않고 권한을 확인하는 `/gift.html?id=...` 주소를 넣는다. 전달 완료 이미지는 덮어쓰기와 삭제를 허용하지 않는다. 미전달 파일만 업로드한 관리자가 정리할 수 있다.

쿠폰번호는 공백·하이픈 제거 후 대문자로 정규화한 SHA-256 해시로 중복을 확인한다. 같은 번호를 다른 당첨 건에 사용할 수 없다. 쪽지·지급 영수증·완료 상태를 한 트랜잭션으로 기록한다. 같은 건을 같은 내용으로 재시도하면 기존 결과를 반환하고, 관리 화면도 서버 발송 내역을 다시 확인한다. 실제 사용·잔액·환불 여부는 구매처에서 확인한다.

## 추천 보상 발송 상태

**추천 보상 발송업체는 미연결이며, 추천 보상은 `awaiting_provider`로 유지한다.** 월말 게임 보상의 직접 구매·쪽지 발송과 별도로 운영한다.

발송 예정 금액과 실제 발송 완료 금액을 구분한다. 업체 계정, 사용 상품 코드, 서버용 API 인증, 발송 번호 및 결제/충전 수단이 준비되면 별도 서버 발송기를 연결해야 한다. 단순히 정책의 상태 값만 변경해서는 발송되지 않는다.

발송기는 지급 건의 고유 키로 중복 요청을 차단하고 업체의 주문 조회/영수증을 대조해야 한다. 응답을 받지 못한 주문은 조회로 확인하기 전 재구매하지 않는다. 발송 직전에 계정·제외 번호·전화번호 변경을 다시 확인한다. 업체 인증정보와 원문 전화번호를 공개 저장소나 클라이언트 코드에 넣지 않는다.

## 운영 위치

- 관리자 화면: `/admin/rewards.html` (관리자 로그인 필요)
- 비공개 스키마: `ojjuda_rewards_internal`
- 추천 집계: `ojjuda_referral_reward_accounting` — UTC 매시 17분
- 월말 마감: `ojjuda_month_end_reward_snapshot` — UTC 매일 14:59, 함수에서 한국 말일만 실행
- 관리자 번호는 비공개 제외 목록에 해시로 등록한다. 실제 번호는 이 문서나 소스에 보관하지 않는다.

초기 마이그레이션은 `rewards_core.sql`, `rewards_referrals.sql`, `rewards_monthly.sql`, `rewards_admin.sql` 순서로 적용한다. 이후 `rewards_message_delivery.sql`을 적용한다(기존 친구 쪽지 마이그레이션 필요). 이미 적용된 운영 데이터베이스에 재실행하지 않는다. 후속 변경은 별도 마이그레이션으로 적용한다.

`tests/rewards-db.sql`은 승인된 데이터베이스 연결에서 실행하는 트랜잭션 회귀 검사다. 테스트 가입자와 지급 기록은 끝에서 롤백된다. 최초의 빈 보상 원장과 월말 마감 시간 외 실행을 전제로 작성되었다. 운영 집계가 누적된 이후에는 격리된 검증 데이터베이스에서 실행한다.

`tests/reward-coupon-db.sql`은 실제 쿠폰을 업로드하지 않고 합성 이미지 메타데이터로 중복 방지, 관리자 제외, 수신자 검증, 쪽지 알림, 실패 시 전체 롤백 및 Storage 권한을 확인한다. 모든 테스트 사용자·쪽지·영수증은 롤백한다. `node --test tests/reward-coupon-ui.test.cjs`는 모의 서버로 등록·재시도, 열람 권한 오류, 계정 전환 시 화면 삭제, 쪽지 링크를 확인한다.
