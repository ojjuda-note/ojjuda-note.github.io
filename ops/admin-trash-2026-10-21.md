# 관리자 휴지통 — 2026-10-21

배포 버전: 0.46.24-beta. 기준 main: c435caf1c479465f283659d850344d265a315c32.

## 동작

- 관리자 최상위에 휴지통을 추가하고 전체 / 탈퇴 계정 / 삭제한 카드 / 삭제한 쪽지 / 기타 보관으로 나눈다. 기존 탈퇴 계정·카드 보관함 링크와 저장된 메뉴 상태는 새 항목으로 연결한다.
- 한국 시간 기준 삭제·탈퇴 시각 + 1개월. 다음 달에 같은 날짜가 없으면 말일. 이미 보관 중인 자료의 더 이른 만료일은 연장하지 않는다.
- 탈퇴 계정정보는 기존 비공개 보관 테이블과 마스킹을 유지한다. 비밀번호·토큰은 복사하지 않는다.
- 일반 삭제 카드는 기존 보관 행과 복구 기능을 유지한다. 탈퇴·상위 카드 삭제 등 물리적 cascade로 없어지는 카드·답글은 본문·태그·작성자 등의 최소 기록만 별도 보관한다. 탈퇴 시 사진 파일·좌표는 기존 절차로 삭제하며 이 기록에는 복구 버튼을 제공하지 않는다.
- 관리자 쪽지 관리에서 휴지통으로 이동할 수 있다. 활성 쪽지 행과 읽음 표식을 제거하므로 대화·알림·활성 관리자 쪽지 검색에 남지 않는다. 한쪽 회원 탈퇴 때도 동일하게 보관한다. 삭제한 쪽지의 전송 재시도는 보관 기간 동안 거부한다.
- 기타에는 기존 운영 보관 자료·만료된 대화와 삭제되는 문의·의견 기록을 모은다. 활성 쪽지·의견·신고를 일괄 삭제하지 않는다. 이미 비워진 폐지 기능의 개인 사진 휴지통에는 새 자료를 복사하지 않는다.
- 계정·카드·기타 운영 보관·새 휴지통은 각각 독립적인 5분 주기 DB 정리 작업을 사용한다. 조회에서는 만료 시각부터 제외한다. 휴지통 열람 기록도 1개월 후 파기한다.
- 사진은 DB 메타데이터만 지우지 않는다. 카드 제거로 만들어진 기존 사진 폐기 표식 중 활성 카드/이벤트에서 참조하지 않는 파일만 Supabase Storage S3 API로 삭제한다. 15분 주기 GitHub 작업, 프로젝트·버킷·경로 검사, 실행 직전 참조 재검사, 삭제 확인, 실패 후 재시도. 백업 저장소와 프로필 사진 media 버킷은 대상이 아니다.

## 권한과 문서

- 새 테이블은 비공개 스키마, RLS 켜짐, anon/authenticated 직접 접근 없음. 공개 함수는 invoker 래퍼이며 내부 함수에서 매 요청 현재 관리자 권한을 확인한다.
- 관리 화면의 계정 변경·권한 오류·늦은 응답 시 자료를 비우고, 본문은 HTML 대신 textContent로 출력한다. 새 비밀키는 클라이언트에 추가하지 않는다.
- 현재 약관 개정안·개인정보처리방침·탈퇴 안내·탈퇴 확인창을 실제 보관 기준에 맞췄다. 과거 정책 보관본과 회원 동의 기록, 2026-11-20 개정 시행 경계는 변경하지 않는다.
- 백업과 기존 신고·보안 로그의 별도 보유 기준은 이 휴지통과 구분하며 변경하지 않는다.
