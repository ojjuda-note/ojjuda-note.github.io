# 축제일정 운영

## 위치와 갱신

- 운영 경로: `https://ojjuda.kr/world.html?game=festival`
- 독립 경로: `https://ojjuda.kr/games/festival-schedule/index.html`
- 오락실 맨 아래 테스트 구역의 `festival` 카드로 실행한다.
- 지도·캘린더·목록은 모두 `games/festival-schedule/events.json`을 사용한다.
- 매일 오후 1시 Asia/Seoul에 연결된 ChatGPT 예약 작업이 공식 자료를 확인하고 변경을 반영한다. 새 행사와 변경 사항뿐 아니라 일정 미정 행사의 날짜 확정·개최 취소·장소 확정도 확인한다. 데이터 파일은 최신 상태를 읽도록 캐시를 재검증한다. 브라우저에서 외부 사이트를 직접 긁지 않는다.
- 새 행사/변경 확인 → 데이터 검증 → 관련 테스트 → GitHub PR 검사 → 병합 → GitHub Pages 배포 확인 순으로 진행한다. 관련 없는 수정은 포함하지 않는다.

## 데이터 형식

루트 객체는 `{ "schemaVersion": 1, "updatedAt": "YYYY-MM-DD", "events": [...] }`이다. `updatedAt`은 이 자료 묶음이 마지막으로 변경된 한국 날짜이며, 모든 행사의 재검증을 의미하지 않는다. 실제 검증일은 항목별 `sourceCheckedAt`이다.

필수 필드:

- `id`: 연도·행사를 식별하는 고유 문자열. 같은 행사 수정 시 유지한다(저장 목록과 캘린더 UID 유지).
- `title`, `category`: 종류는 `local`, `campus`, `film`, `expo` 중 하나.
- `dateStatus`: 생략하거나 `confirmed`이면 날짜가 있는 행사다. 공식 개최 계획은 있으나 구체적 일자가 미정인 행사는 `undecided`로 기록한다. `status`의 취소·연기 여부와 별개다.
- `start`, `end`: 날짜가 있는 행사는 포함되는 시작일·종료일을 `YYYY-MM-DD`로 기록한다. 1일 행사도 둘 다 기록한다. `dateStatus: "undecided"`이면 두 필드를 모두 명시적인 `null`로 기록한다.
- `dateNote`, `dateEvidence`: 일정 미정 행사에 필수인 비어 있지 않은 문자열. `dateNote`는 공식적으로 공개된 시기(예: `2027년 5~6월 예정`) 또는 `일정 발표 전`, `dateEvidence`는 해당 회차의 공식 개최 예고·계획 근거를 요약한다. 근거 URL은 `sourceUrl` 또는 `verificationSources`에도 남긴다. 월·계절만 공개된 것을 임의의 시작일·종료일로 바꾸지 않는다.
- `region`: 서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 전남, 경북, 경남, 제주 중 하나.
- `city`, `venue`, `address`, `lat`, `lng`, `geoApprox`: 대표 행사장. 근사 좌표는 `geoApprox: true`. `geoApprox`는 모든 행사에 boolean으로 기록한다. 지도 핀으로 정확한 입구라고 주장하지 않는다.
- `locationStatus`: 생략하면 비어 있지 않은 주소와 유효한 국내 좌표가 필요하다. `undecided`이면 `venue`에 `장소 미정`을 기록하고 `lat`, `lng`를 모두 명시적인 `null`로 둔다. `planned`이면 `venue`에 공식 예정 장소 이름과 예정임을 표시하고, 좌표를 확인하지 못했거나 여러 예정 장소를 대표할 수 없으면 두 좌표를 모두 `null`로 둔다. 두 상태에서는 `address`를 빈 문자열로 둘 수 있다. 날짜 미정과 장소 미정은 독립적으로 기록한다.
- `summary`, `scheduleNote`, `priceNote`: 확인한 소개·운영 시간·요금. 확인 못 한 정보는 `공식 안내 확인`.
- `accessNote`: 외부인 입장, 나이, 비즈니스데이, 예약, 동의 등 방문 판단에 필요한 조건(해당 시).
- `sourceUrl`, `sourceName`, `sourceCheckedAt`: 근거 URL·기관명·실제 확인 날짜. `verificationSources` 배열에 추가 공식 근거를 보존할 수 있다.
- `status`: `scheduled`(일정으로 진행/예정/종료 자동 계산), `cancelled`, `postponed`.
- 선택 필드: `tags` 문자열 배열.

취소·연기는 기존 항목의 상태와 설명에 명시한다. 확정 일자가 있던 행사가 연기되어 새 일정이 미정이면 이전 날짜를 보존하고 `status: "postponed"` 및 설명으로 알린다. 이를 처음부터 일자가 발표되지 않은 `dateStatus: "undecided"`와 혼동하지 않는다. 새 날짜가 공식 발표되면 같은 ID의 날짜를 수정하고 상태를 `scheduled`로 변경한다. 종료 행사는 `지난 행사 포함` 조회를 위해 남긴다. 복수 장소나 비연속 상영은 공백 기간에도 개최된다고 표시하지 않도록 프로그램별로 분리하거나 세부 일정을 분명히 안내한다.

## 일정·장소 미정 행사

- 해당 연도·회차의 개최를 주최 측이나 지자체가 공식 예고했거나 실제 추진 계획에 명시한 행사만 추가한다. 매년 열렸다는 이유로 다음 회차를 추정하거나 작년 일정을 복사하지 않는다. 개최 여부 자체가 미정인 행사를 정상 개최 예정으로 소개하지 않는다.
- 공식 포털에 월·계절 단위 계획이 남아 있어도 주최 측 최신 공지·모집 공고·변경 안내에 구체적 날짜가 나왔는지 교차 확인한다. 오래된 포털의 `미정` 표기만 근거로 삼지 않는다.
- 일정 미정 행사는 별도 조회와 지도·목록에서 안내할 수 있으나, 이번 주말·이번 달·직접 지정 기간·특정 날짜처럼 날짜 범위를 한정한 검색에는 포함하지 않는다. 달력의 날짜 칸에 배치하거나 D-day를 계산하지 않으며, 날짜 확정 전에는 ICS 파일을 만들지 않는다.
- 위치 미정 행사에는 지도 핀을 생성하지 않는다. 구청·주최 기관의 주소나 전년도 장소를 대신 행사장으로 표시하지 않는다. 공식 예정 장소가 있더라도 좌표가 `null`인 행사는 지도 핀 없이 목록과 상세 정보에서 안내한다.
- 일정이 공식 확정되면 기존 `id`를 유지하고 `dateStatus: "confirmed"`, 실제 `start`·`end`로 갱신한다. 미정 상태의 `dateNote`·`dateEvidence`는 삭제하거나 확정 내용으로 정리해 오래된 문구가 남지 않게 한다. 최신 공식 출처와 실제 `sourceCheckedAt`을 기록한다. 장소도 확정되면 `locationStatus`를 제거하고 주소·좌표·`geoApprox`를 확인해 반영한다.
- 수집 실패나 발표가 없다는 이유로 미정 날짜를 채우거나 검증일을 새로 찍지 않는다. 기존의 확인된 개최 근거는 유지하고, 공식 후속 공지가 확인된 경우에만 변경한다.

## 근거 수집

한국관광공사 대한민국 구석구석, 제주관광공사, 각 지자체·관광재단, 대학·총학생회 공식 공지, 영화제·전시 주최 측·전시장 공식 일정을 우선한다. 현재 진행 중과 가까운 예정 행사를 우선 재확인한다. 전국 여러 지역과 네 종류를 함께 조사한다.

검색 요약만으로 연도를 가정하거나, 작년 일정을 올해 날짜로 바꾸거나, 대학축제 출연진·외부인 입장을 추정하지 않는다. 주최 측 최신 변경 공지가 이전 소개보다 우선한다. 새 데이터가 애매하거나 수집 실패 시 기존 정상 데이터를 지우지 말고 해당 항목의 검증일을 유지한다. 취소·연기·입장 제한을 누락하지 않는다.

## 검증과 배포

```sh
node games/festival-schedule/validate.mjs
node tests/festival-core.test.mjs
node tests/festival-entry.test.cjs
node tests/game-release-refresh.test.cjs
```

파일 변경 시 날짜 순서, 미정 상태와 명시적 `null`의 일치, 공식 개최 근거, 중복 ID, 시도명, 좌표 범위, 필수 출처 URL을 검사한다. `events.json`만 바뀌는 업데이트에는 게임 버전이나 아지트 버전을 올릴 필요가 없다. UI/코드 수정은 루트 `AGENTS.md`에 따라 `festival` 게임 버전과 관련 캐시 리비전을 함께 갱신하고, `game-release.json`·로더 revision·world.html 로더 쿼리를 일치시킨다. 아지트 `version.json` 및 `Go`는 변경하지 않는다.

브라우저에서 검색·지역·기간·종류 필터가 지도/캘린더/목록에 일관되게 적용되는지, 여러 날 행사가 매일 표시되는지, 저장과 상세창·캘린더 내보내기·게임 목록 복귀가 작동하는지 확인한다. 일정 미정 행사가 날짜 칸·기간 한정 결과·ICS에 잘못 포함되지 않는지, 위치 미정 행사에 임의의 지도 핀이 생기지 않는지도 확인한다. 캘린더 파일은 종일 일정이고 종료 다음날을 `DTEND`로 사용한다. 내려받은 파일은 이후 변경을 자동 동기화하지 않는다.

지도 경계는 출처가 표시된 KOSTAT 2018 자료를 간소화한 참고용 경계다. 정확한 최신 행정 경계나 입구 안내로 사용하지 않는다. 상세 지도는 사용자가 선택했을 때 OpenStreetMap 타일을 로드하며 저작자 표시를 유지한다.
