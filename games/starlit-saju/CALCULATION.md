# 별빛 사주팔자 계산 기준

## 계산 범위

`engine.mjs`는 브라우저 안에서 양력·한국 음력 생일을 변환하고 년주·월주·일주·시주를 계산한다. API 호출, 회원 데이터 읽기, 생년월일 저장은 없다. 같은 입력은 같은 결과를 만든다.

- 입력 연도는 1900년부터 현재까지이며, 라이브러리 상한은 2050년이다. 존재하지 않는 생일과 미래 생일·시각은 거절한다.
- 음력 입력은 한국 음력 기준이며 평달과 윤달을 구별한다. `korean-lunar-calendar`가 유효한 날짜인지 확인한 뒤 양력으로 변환한다. 중국 음력 날짜로 대체하지 않는다.
- 입력 시각은 **현대 한국 표준시 UTC+9**다. 출생지 경도에 따른 태양시, 역사적인 UTC+8:30 표준시, 과거 서머타임은 보정하지 않는다. 이 한계는 결과의 `conventions`에도 반환한다.
- 년주는 입춘 순간, 월주는 12절의 교체 순간을 사용한다. `lunar-javascript`가 제공하는 UTC+8 절기 시각과 비교할 때만 한국 시각을 1시간 앞선 시각으로 변환한다. 한국의 일주·시주를 계산할 때 날짜나 시간을 1시간 빼지 않는다.
- 일주는 자정에 바뀐다. 시주는 `lunar-javascript`의 공식 `EightChar` 기본 `sect=2`와 같은 야자시 분리법이다. 23:00~23:59의 일주는 당일이지만 자시의 시주는 다음 일간을 사용하며, 다음 날 00:00~00:59까지 동일한 시주로 이어진다. 23시에 일주도 바꾸는 유파와는 결과가 다를 수 있다.
- 오행은 표시된 천간·지지의 대표 오행을 각각 한 글자로 센다. 지장간, 월령·계절의 세기, 합·충, 신강·신약, 대운 등을 종합한 수치가 아니다.

## 불확실한 출생시각

`hour: null`은 시간 모름이며 `hour: 0`과 구별한다. 시주를 임의의 시간으로 채우지 않는다. 해당 한국 날짜의 시작과 끝에서 년·월주가 달라지면 그 주도 확정하지 않고 두 후보를 반환한다.

입력이 분 단위이므로, 입력한 1분 안에 절기가 바뀌는 경우 역시 해당 년·월주를 확정하지 않는다. 결과의 `warnings`, `pillars[].uncertain`, `pillars[].alternatives`를 표시해야 한다. 오행 집계에는 확정된 글자만 포함하며 `knownCharacterCount`는 2·4·6·8 중 하나다.

## 인터페이스

```js
import { calculateSaju } from './engine.mjs';
const result = calculateSaju({
  year: 2005, month: 12, day: 23,
  calendar: 'solar', leapMonth: false,
  hour: 8, minute: 37,
});
```

잘못된 입력은 한국어 `message`와 안정된 `code`를 가진 `SajuInputError`를 던진다. 코드: `input`, `calendar`, `year`, `date`, `leap-month`, `time`, `clock`, `future`, `range`.

주요 반환값:

- `solar`, `lunar`: 변환된 날짜와 표시용 `label`; `solar.iso`, `lunar.leapMonth` 포함.
- `timeKnown`, `timeLabel`: 알려진 시각인지와 표시용 문구.
- `pillars`: `year`, `month`, `day`, `hour` 순서. 각 항목에 한자·한글·천간·지지·확정 여부·후보가 있다. 미확정이면 `hanja`, `hangul`, `stem`, `branch`는 `null`이다.
- `dayMaster`: 확정된 일간의 한자·한글·오행·음양.
- `elements`, `knownCharacterCount`: 확정된 글자만 집계한 목·화·토·금·수.
- `warnings`, `conventions`: 사용자가 결과를 이해할 때 필요한 제한과 기준.

## 상세 풀이의 계산 자료 — 2026-11-13

`fortune-data.mjs`의 `analyzeFortune(chart, { year, now })`는 기존 계산 결과에서 **확정된 원국만** 사용해 상세 풀이의 근거를 만든다. 이름·성별을 추가로 받지 않는다. 선택 연도는 1900~2050년이며, 생년보다 앞선 연도는 거절한다.

### 원국과 십성

- 오행·음양은 확정된 천간·지지를 각각 한 글자로 센다. 많은 오행은 단순히 글자가 가장 많은 오행이며 신강·신약, 용신 또는 유리한 오행이라는 뜻이 아니다. 미확정 주가 있으면 `complete=false`이며, `missingElements`는 확인된 글자에만 보이지 않는 오행이다.
- 태어난 계절은 **확정된 월지**로 읽는다. 寅卯辰은 봄, 巳午未는 여름, 申酉戌은 가을, 亥子丑은 겨울이다. 월지가 불확정이면 계절을 추정하지 않는다.
- 십성은 일간을 기준으로 오행의 생극 관계와 **대상 천간의 음양**을 적용한다. 일간 그 자체는 `日主`이므로 `gods` 목록에 비견으로 중복 집계하지 않는다.
- 지지 십성은 지지의 음양을 그대로 쓰지 않고 지장간의 **본기 천간**을 사용한다. 子→癸, 丑→己, 寅→甲, 卯→乙, 辰→戊, 巳→丙, 午→丁, 未→己, 申→庚, 酉→辛, 戌→戊, 亥→壬이다. 여기서는 나머지 중기·여기의 십성이나 계절별 가중치를 합산하지 않는다.
- 십성 10종의 매핑과 본기 순서는 고정된 `lunar-javascript` 소스의 `LunarUtil.SHI_SHEN`, `ZHI_HIDE_GAN`, 공식 `EightChar` 예제와 교차 확인했다. 중국어 `七杀`는 한국어 `편관`, 별칭 `칠살`로 표시한다.

### 합·충

천간 5합, 지지 6합과 6충의 정해진 글자 짝만 탐지한다. 원국 안의 쌍과 선택한 세운·월운 대 원국의 쌍을 구별한다. 천간합은 甲己·乙庚·丙辛·丁壬·戊癸, 지지육합은 子丑·寅亥·卯戌·辰酉·巳申·午未, 지지충은 子午·丑未·寅申·卯酉·辰戌·巳亥이다. 이 표는 고정 소스의 `HE_GAN_5`, `HE_ZHI_6`, `CHONG`과 일치한다.

짝이 발견된 것은 구조적 대응이며, 합화가 실제로 성립했다거나 길흉·사건이 발생한다는 판정이 아니다. 형·파·해·삼합·삼회 또는 격국 판정은 추가하지 않는다.

### 세운과 12개월 월운

선택 연도의 세운은 해당 연도 **입춘 순간부터 다음 연도 입춘 전까지**다. 년간지는 입춘 뒤의 날짜에서 `getYearInGanZhiExact()`로 읽는다. `year`는 사용자가 선택한 양력 연도, `currentYear`와 `currentMonth`는 현재 한국의 양력 년·월, `currentSolarTermYear`는 현재 입춘 기준의 절기년이다.

월운의 1~12월은 각 양력월 15일이 속한 절기월이다. 1월은 소한~입춘, 2월은 입춘~경칩, …, 12월은 대설~다음 해 소한이다. 중순 시점의 `getMonthInGanZhiExact()`로 월간지를 읽고, `getPrevJie(false)`·`getNextJie(false)`로 실제 절입 시각을 얻는다. 중국 기준 UTC+8 시각에 1시간을 더해 한국 UTC+9 시각을 표시하며, 이때 날짜·연도 변경도 반영한다. 예를 들어 2026년 망종은 이 라이브러리 기준 중국 시각 6월 5일 23:48:21, 한국 시각 6월 6일 00:48:21이다.

`months[].yearHanja`와 `solarTermYear`에는 그 월운이 속한 연주와 절기년이 별도로 있다. 따라서 2026년 1월 월운의 년주는 乙巳, 절기년은 2025이며, 입춘 뒤 2월부터 丙午·2026으로 바뀐다. `isCurrent`는 달력 월번호가 아니라 **시작 시각 이상·종료 시각 미만**의 실제 구간으로 정한다. 새해 1월 1일부터 소한 전까지는 직전 연도의 12월 절기월이므로 새해의 월운 카드에 현재 표시를 붙이지 않고 안내 문구를 제공한다.

### 확정된 원국의 추가 참고표

`profile.reference`에는 확정된 각 주의 전체 지장간과 각 지장간의 일간 기준 십성, 십이운성, 납음, 순과 공망을 별도 자료로 제공한다. `reference-data.mjs`의 표는 같은 고정 원본 `lunar-javascript 1.7.8`의 `ZHI_HIDE_GAN`, `CHANG_SHENG_OFFSET`, `CHANG_SHENG`, `NAYIN`, `XUN`, `XUN_KONG`에서 추출했다. 공식 문서는 <https://6tail.cn/calendar/lunar.bazi.html>이며, 원본 MIT 라이선스는 `vendor/lunar-LICENSE.txt`에 있다.

이 표는 이미 확정한 원국의 글자로 조회하며 달력·절기·일주·시주를 다시 계산하지 않는다. 미확정 년주·월주·시주는 제외한다. 지장간은 원본의 전체 목록과 순서를 유지하고 첫 글자만 본기로 표시한다. 나머지는 자료 순서만 표시하여 중기·여기 등 학파별 세부 명칭을 임의로 붙이지 않는다. 전체 지장간은 기존 오행·음양 개수나 7곳의 천간·지지 본기 십성 집계에 합산하지 않는다.

십이운성은 공식 `EightChar._getDiShi`와 같이 일간의 음양과 각 주의 지지를 기준으로 조회한다. 병·사·묘 등은 전통 분류의 이름이며 의학적 질병·사망·수명 예측이 아니다. 납음은 간지에 붙은 원문 명칭만 표시한다. 순·공망은 각 주 자체의 10간지 묶음과 그 묶음에 없는 두 지지를 표시하며, 일주 기준의 타주 공망 적용·효력·길흉을 추가 판단하지 않는다.

고정 원본의 2005년 12월 23일 예제에서 네 주의 전체 지장간·십성·십이운성·납음·순·공망을 공식 API와 비교했다. 60개 일주 전체의 십이운성·납음·순·공망도 같은 API와 교차 확인하며, 시간 모름·입춘 경계 미확정 제외를 별도로 검증한다.

### 해와 달의 추가 참고표

`annual.reference`와 `months[].reference`에도 해당 세운·월운의 전체 지장간과 십성, 십이운성, 납음, 순·공망을 제공한다. 십성과 십이운성의 기준은 선택한 해나 달의 천간이 아니라 **사용자의 확정된 출생 일간**이다. 각 자료에는 `scope`, `dayMaster`, 출처와 주의사항을 함께 둔다.

이 자료는 기존에 계산한 시간 간지를 조회하는 참고표다. 원국의 글자나 오행·음양·주요 십성 개수에 추가하지 않는다. 원국과 세운·월운 사이에 공망이 작용한다거나, 납음과 십이운성으로 실제 사건·질병·수명을 판정하지 않는다. 전체 참고 행을 해당 상품의 근거표와 복사문에 보존한다.

10개 출생 일간과 60개 간지의 조합을 연간·월간 각각 대조하여 총 1,200건에서 고정된 공식 EightChar API와 일치하는지 확인한다. 이 검사는 원자료를 충실히 구현했는지 확인하는 것이며, 전통 해석의 미래 예측 능력을 검증하는 것은 아니다.

### 외부 달력자료 대조와 출처 범위

2026년 소한부터 대설까지 월운의 시작이 되는 12절의 한국 시각을 [한국천문연구원 2026년 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2026)의 분 단위 시각과 대조했다. 고정 라이브러리의 초 단위 값과의 차이는 각 절에서 30초 이내다. 해당 페이지는 공식 월력요항 발표 전의 참고자료라고 명시되어 있으므로, 공식 발표문이나 초 단위 정확성 검증으로 표시하지 않는다. 2026년 연간·월별 상품에만 이 대조 자료를 출처로 표시한다.

`sources.mjs`는 자료별 제목, 제공처, URL, 사용한 범위와 한계를 제공한다. 한국 음력 변환 라이브러리, EightChar 공식 문서, 한국민족문화대백과사전의 사주 개념을 서로 다른 용도로 구분한다. 백과사전이나 달력기관이 개인의 운세를 검증·보증했다고 표현하지 않는다. 평생운 출처와 복사문은 선택 연도에 영향을 받지 않는다.

### 상세 풀이의 범위

평생운은 원국의 장기적인 주제 풀이이다. 이름·성별·대운 순행·역행·기산 나이를 이용하는 10년 대운이나 나이별 사건을 계산한 결과로 표시하지 않는다. 세운·월운도 확정된 원국과 시간 간지의 상징적 관계만 제공하며, 난수·운세 점수·임의의 행운 수치로 내용을 채우지 않는다.

```sh
node --test tests/saju-engine.test.mjs tests/saju-fortune.test.mjs
```

추가 검증: 십성 10종, 공식 예제 교차 확인, 지지 본기의 음양, 일간 중복 제외, 2026·2027 세운, 12절 월운의 연속성, 한국 시각의 절기 날짜 변경, 1월 이전 연주, 절입 순간의 현재 표시, 시간 모름·불확정 월주·입력 불변성.

## 쉬운 풀이와 원자료를 읽는 순서 — 2026-11-13

각 장은 제목, 핵심을 먼저 말하는 소제목, 쉬운 상세 문단 순서로 제공한다. 소제목에는 해당 장의 실제 요점을 담고, 아래 문단에서 용어의 뜻과 계산 결과를 풀어 설명한다. 생활 속 상황을 들 때는 예시임을 밝히며, 글자의 개수를 실제 능력·재산·사건의 발생 확률로 바꾸지 않는다. 모르는 출생시간과 절기 경계의 후보도 기존 계산 상태를 유지한다.

원래 계산 문장, 적용한 해석 규칙, 공통 참고 설명은 각 장의 펼치기 영역에 모두 남긴다. 전체 계산자료와 용어 설명도 별도로 확인할 수 있으며, 복사에는 해당 상품의 쉬운 풀이와 원래 근거를 함께 포함한다. 이 변경은 화면과 설명의 개선이며 달력·십성·합충·참고표·결제 계산을 바꾸지 않는다.

### 읽기 편의와 근거가 있는 생활 제안

구매한 풀이를 먼저 읽을 수 있게 다른 상품 선택판은 기본 접힘으로 둔다. 현재 읽는 상품과 재조회 조건은 밖에서 확인할 수 있다. 보통·크게 글자 조절, 단원 바로가기, 월별 이동·모두 펼치기는 결제와 관계없는 읽기 기능이다. 생시나 절기 경계가 미확정이라는 중요한 안내는 원자료를 펼치기 전에도 보인다.

생활 제안은 계산 자료에서 실제로 확인한 십성과 합·충에 연결한다. 제안마다 제목, 그 제안을 한 이유, 해 볼 일, 함께 살필 점, 관련 `factIds`, `origin: 'service-advice'`를 둔다. 원자료의 인용문이나 전통의 확정 판단으로 제시하지 않고 오쭈다가 쓴 생활 제안임을 밝힌다. 같은 규칙에 같은 제안 문장이 쓰일 수 있지만 근거가 없는 달에 다른 달의 점괘를 임의로 배정하지 않는다.

12개월에 걸쳐 생활 제안의 중복 제거 상태를 공유해 뒤쪽 달의 조언이 사라지던 부분을 고친다. 각 달은 그달에 확인된 자료를 근거로 제안을 온전히 제공하며, 복사문도 해당 달의 이유와 실천 내용을 포함한다. 계산하지 않은 대운·용신·미래 사건은 추가하지 않는다.

## 사주 상세 풀이 이용권 — 항목마다 10쭈

일반 회원은 **평생운·올해운·월별운을 각각 10쭈**에 구매한다. 월별운 한 항목에는 선택한 연도의 12개월이 모두 포함되며, 개별 월을 열 때 다시 차감하지 않는다. 같은 회원·같은 출생 정보·같은 항목·같은 연도의 재열기는 무료다. 평생운에는 선택 연도가 없으며, 올해운·월별운의 다른 연도를 새로 구매하면 각각 10쭈다.

| 제품 키 | 대상 | 이용권의 연도 | 서버 가격 |
| --- | --- | --- | --- |
| `lifelong` | 원국에 근거한 평생운 | `0` (`null`도 `0`으로 정규화) | 10쭈 |
| `annual` | 선택 연도의 연간운 | 1900~2050 | 10쭈 |
| `monthly` | 선택 연도의 12개월 월운 | 1900~2050 | 10쭈 |

서버는 생년월일·출생시각·이름·성별·풀이 본문을 받거나 저장하지 않는다. 클라이언트가 회원별 구분값과 정규화된 양력 생일·시각으로 만든 64자리 SHA-256 `chart_key`만 출생 정보를 구별하는 데 사용한다. 이 해시는 계정에 연결된 결제 식별값이며 생일 원문·상세 풀이 자체는 포함하지 않는다. 시간을 모르는 입력과 시각을 아는 입력은 별도 출생 정보다. 선택 연도는 출생 정보 해시가 아니라 항목 이용권의 `year`로 구분한다.

- 구매: `saju_reading_buy_v2(p_request_id uuid, p_chart_key text, p_topic text, p_year integer, p_expected_user uuid, p_verify_only boolean default false)`.
- 조회: `saju_reading_status_v2(p_chart_key text default null)`. `null`은 잔고·가격만 조회하며 출생 정보별 이용권을 나열하지 않는다.
- 구매 성공: `ok`, `entitled`, 원래 `request_id`, `chart_key`, `topic`, `year`, 고정 `price:10`, 현재 `coins`, 이번 `charged:10|0`, `replayed`, `entitlement_replayed`, `legacy_bundle`, `paid_at`, `product:'saju'`, `entitlement_version:2`.
- 조회 성공: 현재 `coins`, `prices:{lifelong:10,annual:10,monthly:10}`, 해당 출생 정보의 `entitlements:[{topic,year,request_id,paid_at,price}]`, 기존 전체 이용권이 있으면 `bundle_entitlement:{request_id,paid_at,price}`. 없으면 각각 빈 배열과 `null`이다.
- 확인 전용 구매에서 해당 항목 이용권과 기존 전체 이용권이 모두 없으면 `reason:'not_found'`이며 차감하지 않는다.

구매 함수는 로그인·기대 계정·실제 회원·정지·지갑·잔고를 확인한다. `p_expected_user`가 서버의 `auth.uid()`와 다르거나 값이 없으면 `account_changed`로 중단한다. 요청 전송 중 다른 탭에서 계정이 바뀌어 SDK가 새 계정의 토큰을 사용하더라도 새 계정에 과금하지 않는다.

요청 UUID 잠금과 지갑 행 잠금, `(user_id,chart_key,topic,year)` 기본키로 중복 차감을 막는다. 잔고 차감·결제 내역·항목 이용권 생성은 같은 트랜잭션이며 중간 오류는 차감을 되돌린다. 거래 내역에는 `kind:'saju_reading_v2'`, 사주 항목 제목, 대상 연도를 기록한다. 하나의 개별 구매 UUID를 다른 회원·출생 정보·항목·연도에 재사용하면 `request_conflict`로 거절한다. 계정을 삭제하면 기존 지갑·거래 내역과 함께 항목 이용권도 외래키로 정리된다.

### 기존 전체 이용권 보호

이전 v1의 전체 사주 이용권이 있는 회원은 같은 출생 정보의 평생운과 모든 연도의 연간운·월별운을 추가 차감 없이 계속 연다. 새 v2 응답에 `legacy_bundle:true`와 기존 전체 이용권의 `request_id`를 돌려주며, 복구 과정에서 새 유료 거래나 항목 이용권을 생성하지 않는다. 같은 항목의 개별 이용권이 이미 있으면 그 영수증을 먼저 돌려준다. 기존 전체 이용권의 UUID는 같은 출생 정보의 다른 포함 항목·연도에도 쓸 수 있다.

새 전체 이용권을 만들 수 없도록 기존 v1 구매 함수의 공개·내부 3인자/4인자 실행 권한을 모두 회수한다. v1의 기존 영수증 검증과 자기 계정 조회는 읽기 전용으로 유지한다. 이미 적용된 두 마이그레이션은 수정하지 않고, `saju_category_purchases_v2` 마이그레이션에서 새 테이블·함수와 권한 변경을 추가한다.

테이블은 비공개 `ojjuda_saju_internal` 스키마에 있고 RLS를 켰다. 외부 회원에게 테이블 직접 접근이나 영수증 조립 권한을 주지 않는다. 내부 구매·조회 함수만 제한된 `SECURITY DEFINER`를 쓰고, 공개 RPC는 `SECURITY INVOKER`, 모든 함수는 빈 `search_path`를 사용한다. 확인된 관리자 미리보기는 프런트의 기존 관리자 확인 흐름에서 결제 호출을 생략한다.

```sh
node tests/saju-payment-db.test.cjs
```

이 검증은 PGlite의 임시 데이터베이스에서만 실행한다. 기존 v1 결제를 만든 뒤 v2로 실제 업그레이드하여 항목별 10쭈·대상 연도 분리·12개월 묶음·재시도·같은 항목 재열기·계정 분리·전송 중 계정 불일치 차단·v1 구매 권한 회수·기존 전체 이용권 복구·개별 영수증 우선·잔고 부족·정지·회원 삭제·권한·트랜잭션 실패 시 원복·기존 타로 및 사진 결제 트리거 호환성을 확인한다. 재시도 묶음 검사는 단일 PGlite 연결에서 실행되며, 실제 다중 연결 부하 시험은 아니다.
