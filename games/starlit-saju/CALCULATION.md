# 별빛 사주팔자 계산 기준

## 계산 범위

`engine.mjs`는 브라우저 안에서 양력·한국 음력 생일을 변환하고 년주·월주·일주·시주를 계산한다. API 호출, 회원 데이터 읽기, 생년월일 저장은 없다. 같은 입력은 같은 결과를 만든다.

- 입력 연도는 1900년부터 현재까지이며, 라이브러리 상한은 2050년이다. 존재하지 않는 생일과 미래 생일·시각은 거절한다.
- 음력 입력은 한국 음력 기준이며 평달과 윤달을 구별한다. `korean-lunar-calendar`가 유효한 날짜인지 확인한 뒤 양력으로 변환한다. 중국 음력 날짜로 대체하지 않는다.
- 입력 시각은 **현대 한국 표준시 UTC+9**다. 출생지 경도에 따른 태양시, 역사적인 UTC+8:30 표준시, 과거 서머타임은 보정하지 않는다. 이 한계는 결과의 `conventions`에도 반환한다.
- 년주는 입춘 순간, 월주는 12절의 교체 순간을 사용한다. `lunar-javascript`가 제공하는 UTC+8 절기 시각과 비교할 때만 한국 시각을 1시간 앞선 시각으로 변환한다. 한국의 일주·시주를 계산할 때 날짜나 시간을 1시간 빼지 않는다.
- 일주는 자정에 바뀐다. 시주는 `lunar-javascript`의 공식 `EightChar` 기본 `sect=2`와 같은 야자시 분리법이다. 23:00~23:59의 일주는 당일이지만 자시의 시주는 다음 일간을 사용하며, 다음 날 00:00~00:59까지 동일한 시주로 이어진다. 23시에 일주도 바꾸는 유파와는 결과가 다를 수 있다.
- 오행은 표시된 천간·지지의 대표 오행을 각각 한 글자로 센다. 지장간, 월령·계절의 세기, 합·충, 신강·신약, 대운 등을 종합한 수치가 아니다.

## 불확실한 출생시각

`hour: null`은 시간 모름이며 `hour: 0`과 구별한다. 시주를 임의의 시간으로 채우지 않는다. 해당 한국 날짜의 시작과 끝에서 년·월주가 달라지면 그 주도 확정하지 않고 두 후보를 반환한다.

입력이 분 단위이므로, 입력한 1분 안에 절기가 바뀌는 경우 역시 해당 년·월주를 확정하지 않는다. 결과의 `warnings`, `pillars[].uncertain`, `pillars[].alternatives`를 표시해야 한다. 오행 집계에는 확정된 글자만 포함하며 `knownCharacterCount`는 2·4·6·8 중 하나다.

## 인터페이스

```js
import { calculateSaju } from './engine.mjs';
const result = calculateSaju({
  year: 2005, month: 12, day: 23,
  calendar: 'solar', leapMonth: false,
  hour: 8, minute: 37,
});
```

잘못된 입력은 한국어 `message`와 안정된 `code`를 가진 `SajuInputError`를 던진다. 코드: `input`, `calendar`, `year`, `date`, `leap-month`, `time`, `clock`, `future`, `range`.

주요 반환값:

- `solar`, `lunar`: 변환된 날짜와 표시용 `label`; `solar.iso`, `lunar.leapMonth` 포함.
- `timeKnown`, `timeLabel`: 알려진 시각인지와 표시용 문구.
- `pillars`: `year`, `month`, `day`, `hour` 순서. 각 항목에 한자·한글·천간·지지·확정 여부·후보가 있다. 미확정이면 `hanja`, `hangul`, `stem`, `branch`는 `null`이다.
- `dayMaster`: 확정된 일간의 한자·한글·오행·음양.
- `elements`, `knownCharacterCount`: 확정된 글자만 집계한 목·화·토·금·수.
- `warnings`, `conventions`: 사용자가 결과를 이해할 때 필요한 제한과 기준.

## 상세 풀이의 계산 자료 — 2026-11-13

`fortune-data.mjs`의 `analyzeFortune(chart, { year, now })`는 기존 계산 결과에서 **확정된 원국만** 사용해 상세 풀이의 근거를 만든다. 이름·성별을 추가로 받지 않는다. 선택 연도는 1900~2050년이며, 생년보다 앞선 연도는 거절한다.

### 원국과 십성

- 오행·음양은 확정된 천간·지지를 각각 한 글자로 센다. 많은 오행은 단순히 글자가 가장 많은 오행이며 신강·신약, 용신 또는 유리한 오행이라는 뜻이 아니다. 미확정 주가 있으면 `complete=false`이며, `missingElements`는 확인된 글자에만 보이지 않는 오행이다.
- 태어난 계절은 **확정된 월지**로 읽는다. 寅卯辰은 봄, 巳午未는 여름, 申酉戌은 가을, 亥子丑은 겨울이다. 월지가 불확정이면 계절을 추정하지 않는다.
- 십성은 일간을 기준으로 오행의 생극 관계와 **대상 천간의 음양**을 적용한다. 일간 그 자체는 `日主`이므로 `gods` 목록에 비견으로 중복 집계하지 않는다.
- 지지 십성은 지지의 음양을 그대로 쓰지 않고 지장간의 **본기 천간**을 사용한다. 子→癸, 丑→己, 寅→甲, 卯→乙, 辰→戊, 巳→丙, 午→丁, 未→己, 申→庚, 酉→辛, 戌→戊, 亥→壬이다. 여기서는 나머지 중기·여기의 십성이나 계절별 가중치를 합산하지 않는다.
- 십성 10종의 매핑과 본기 순서는 고정된 `lunar-javascript` 소스의 `LunarUtil.SHI_SHEN`, `ZHI_HIDE_GAN`, 공식 `EightChar` 예제와 교차 확인했다. 중국어 `七杀`는 한국어 `편관`, 별칭 `칠살`로 표시한다.

### 합·충

천간 5합, 지지 6합과 6충의 정해진 글자 짝만 탐지한다. 원국 안의 쌍과 선택한 세운·월운 대 원국의 쌍을 구별한다. 천간합은 甲己·乙庚·丙辛·丁壬·戊癸, 지지육합은 子丑·寅亥·卯戌·辰酉·巳申·午未, 지지충은 子午·丑未·寅申·卯酉·辰戌·巳亥이다. 이 표는 고정 소스의 `HE_GAN_5`, `HE_ZHI_6`, `CHONG`과 일치한다.

짝이 발견된 것은 구조적 대응이며, 합화가 실제로 성립했다거나 길흉·사건이 발생한다는 판정이 아니다. 형·파·해·삼합·삼회 또는 격국 판정은 추가하지 않는다.

### 세운과 12개월 월운

선택 연도의 세운은 해당 연도 **입춘 순간부터 다음 연도 입춘 전까지**다. 년간지는 입춘 뒤의 날짜에서 `getYearInGanZhiExact()`로 읽는다. `year`는 사용자가 선택한 양력 연도, `currentYear`와 `currentMonth`는 현재 한국의 양력 년·월, `currentSolarTermYear`는 현재 입춘 기준의 절기년이다.

월운의 1~12월은 각 양력월 15일이 속한 절기월이다. 1월은 소한~입춘, 2월은 입춘~경칩, …, 12월은 대설~다음 해 소한이다. 중순 시점의 `getMonthInGanZhiExact()`로 월간지를 읽고, `getPrevJie(false)`·`getNextJie(false)`로 실제 절입 시각을 얻는다. 중국 기준 UTC+8 시각에 1시간을 더해 한국 UTC+9 시각을 표시하며, 이때 날짜·연도 변경도 반영한다. 예를 들어 2026년 망종은 이 라이브러리 기준 중국 시각 6월 5일 23:48:21, 한국 시각 6월 6일 00:48:21이다.

`months[].yearHanja`와 `solarTermYear`에는 그 월운이 속한 연주와 절기년이 별도로 있다. 따라서 2026년 1월 월운의 년주는 乙巳, 절기년은 2025이며, 입춘 뒤 2월부터 丙午·2026으로 바뀐다. `isCurrent`는 달력 월번호가 아니라 **시작 시각 이상·종료 시각 미만**의 실제 구간으로 정한다. 새해 1월 1일부터 소한 전까지는 직전 연도의 12월 절기월이므로 새해의 월운 카드에 현재 표시를 붙이지 않고 안내 문구를 제공한다.

### 확정된 원국의 추가 참고표

`profile.reference`에는 확정된 각 주의 전체 지장간과 각 지장간의 일간 기준 십성, 십이운성, 납음, 순과 공망을 별도 자료로 제공한다. `reference-data.mjs`의 표는 같은 고정 원본 `lunar-javascript 1.7.8`의 `ZHI_HIDE_GAN`, `CHANG_SHENG_OFFSET`, `CHANG_SHENG`, `NAYIN`, `XUN`, `XUN_KONG`에서 추출했다. 공식 문서는 <https://6tail.cn/calendar/lunar.bazi.html>이며, 원본 MIT 라이선스는 `vendor/lunar-LICENSE.txt`에 있다.

이 표는 이미 확정한 원국의 글자로 조회하며 달력·절기·일주·시주를 다시 계산하지 않는다. 미확정 년주·월주·시주는 제외한다. 지장간은 원본의 전체 목록과 순서를 유지하고 첫 글자만 본기로 표시한다. 나머지는 자료 순서만 표시하여 중기·여기 등 학파별 세부 명칭을 임의로 붙이지 않는다. 전체 지장간은 기존 오행·음양 개수나 7곳의 천간·지지 본기 십성 집계에 합산하지 않는다.

십이운성은 공식 `EightChar._getDiShi`와 같이 일간의 음양과 각 주의 지지를 기준으로 조회한다. 병·사·묘 등은 전통 분류의 이름이며 의학적 질병·사망·수명 예측이 아니다. 납음은 간지에 붙은 원문 명칭만 표시한다. 순·공망은 각 주 자체의 10간지 묶음과 그 묶음에 없는 두 지지를 표시하며, 일주 기준의 타주 공망 적용·효력·길흉을 추가 판단하지 않는다.

`stage-reading.mjs`는 이미 계산된 십이운성에 《삼명통회》 권2 「論五行旺相休囚死並寄生十二宫」의 이름 뜻과 순환 비유를 연결한다. [식전고적의 원문](https://www.shidianguji.com/zh/book/SK1610/chapter/1kf5v6ol1tqg5)을 확인했으며, 원문이 생왕을 무조건 길하게, 사절을 무조건 흉하게 보지 말라고 설명하는 범위도 보존한다. 열두 기본 정의는 공통 참고 설명이며 독립된 개인별 운세 열두 편이 아니다. 실제 확인된 모든 원국 자리와 해당 세운·월운을 각각 연결하고, 근거 ID를 그대로 남긴다. 생활 질문은 서비스가 작성한 예시로 따로 표시하며, 나이별 대운·건강·수명·사건 예측으로 확대하지 않는다.

`deeper-reading.mjs`는 각 지장간의 글자·본기 여부·십성을 하나씩 설명하고, 실제 십성 코드와 위치를 생활 주제에 연결한다. 원국의 같은 코드, 같은 묶음의 다른 코드, 확인되지 않은 이름을 구별하며 해당 시기의 합·충도 모두 근거에 연결한다. 같은 코드가 두 자리에 있으면 두 근거를 하나의 설명에 잇고 별개 예측처럼 늘리지 않는다. `deeper-reading-data.mjs`의 생활 장면·질문과 두 주제의 연결은 서비스가 쓴 공통 해설이며 `service-reference`로 구분한다. 전통 원문의 인용이나 개인의 실제 경험을 확인한 사실로 표시하지 않는다. 평생운에는 숨은 글자와 함께 나온 주제, 연간운에는 일·돈의 상세 설명, 월별운에는 관계·연애·일·돈·배움의 상세 설명을 제공한다. 새 단원도 기존 사실 ID를 사용하고 전체 복사 및 상품·기간 범위를 보존한다.

고정 원본의 2005년 12월 23일 예제에서 네 주의 전체 지장간·십성·십이운성·납음·순·공망을 공식 API와 비교했다. 60개 일주 전체의 십이운성·납음·순·공망도 같은 API와 교차 확인하며, 시간 모름·입춘 경계 미확정 제외를 별도로 검증한다.

### 해와 달의 추가 참고표

`annual.reference`와 `months[].reference`에도 해당 세운·월운의 전체 지장간과 십성, 십이운성, 납음, 순·공망을 제공한다. 십성과 십이운성의 기준은 선택한 해나 달의 천간이 아니라 **사용자의 확정된 출생 일간**이다. 각 자료에는 `scope`, `dayMaster`, 출처와 주의사항을 함께 둔다.

이 자료는 기존에 계산한 시간 간지를 조회하는 참고표다. 원국의 글자나 오행·음양·주요 십성 개수에 추가하지 않는다. 원국과 세운·월운 사이에 공망이 작용한다거나, 납음과 십이운성으로 실제 사건·질병·수명을 판정하지 않는다. 전체 참고 행을 해당 상품의 근거표와 복사문에 보존한다.

10개 출생 일간과 60개 간지의 조합을 연간·월간 각각 대조하여 총 1,200건에서 고정된 공식 EightChar API와 일치하는지 확인한다. 이 검사는 원자료를 충실히 구현했는지 확인하는 것이며, 전통 해석의 미래 예측 능력을 검증하는 것은 아니다.

2026년 소한부터 대설까지 월운의 시작이 되는 12절의 한국 시각을 [한국천문연구원 2026년 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?search_year=2026)의 분 단위 시각과 대조했다. 고정 라이브러리의 초 단위 값과의 차이는 각 절에서 30초 이내다. 해당 페이지는 공식 월력요항 발표 전의 참고자료라고 명시되어 있으므로, 공식 발표문이나 초 단위 정확성 검증으로 표시하지 않는다. 2026년 연간·월별 상품에만 이 대조 자료를 출처로 표시한다.

### 성별을 반영한 10년 대운 — 2026-11-13

`daeun.mjs`의 `analyzeDaeun(chart, { gender, now })`는 `calculateSaju`가 만든 한국 양력 날짜와 확정된 출생시각, `male` 또는 `female`을 받는다. `gender: null`이면 성별 선택 안내만 반환한다. 이름·생년월일 저장·결제는 이 모듈의 역할이 아니며 입력 원국도 변경하지 않는다. 평생운 10쭈와 전체 풀이 최대 30쭈의 기존 범위에 포함한다.

- 출생 년간은 양력 1월 1일이 아닌 **입춘 순간**으로 정한 기존 년주를 사용한다. 양간의 남성과 음간의 여성은 순행, 음간의 남성과 양간의 여성은 역행한다. 월주의 다음 또는 이전 간지부터 60갑자 순서로 9개 대운을 배치한다.
- 기산은 고정된 `lunar-javascript 1.7.8`의 `getYun(gender, 2)`를 사용한다. 순행은 출생부터 다음 **절**까지, 역행은 앞선 **절**부터 출생까지를 센다. 중기나 양력 월초를 대용하지 않는다. 분 차이를 4,320분=1년, 360분=1개월, 12분=1일, 남은 1분=2시간으로 환산한다.
- 라이브러리의 절기 시각은 UTC+8이므로 **한국 출생 시각을 한 시간 빼서 같은 순간**으로 비교한다. 라이브러리 년·월간지가 기존 원국과 일치하는지 검사한다. 일주·시주·십성의 기준 일간은 기존 한국 원국을 그대로 유지한다.
- 환산한 연·월·일·시간은 **원래 한국 양력 출생 시각에 차례대로 더한다.** 연·월 이동으로 같은 날짜가 없는 달은 말일로 맞춘다. 중국 달력 시각에서 먼저 더한 뒤 한 시간 옮기면 자정과 월말에서 날짜가 어긋날 수 있으므로 그 방법을 사용하지 않는다. 예: 한국 1990-01-31 00:30, 여성은 1년 5개월 23일 16시간을 더해 1991-07-23 16:30에 시작한다.
- 첫 시작 시각을 기준으로 각각 10년씩 다음 구간을 만든다. `startsAt`·`endsAt`은 `+09:00` ISO이며 **시작 포함·끝 미포함**이다. `now`는 현재 구간 표시만 바꾸며 계산된 대운 순서와 날짜를 바꾸지 않는다. 첫 시작 전과 9개 표시 범위 뒤는 `currentIndex: null`이고 `currentState`로 구별한다. 9개는 표시 범위이며 수명을 뜻하지 않는다.
- 기산의 연·월·일·시간은 `startAge`에 별도로 보존한다. 카드의 `startAgeYears`·`endAgeYears`는 **한국 양력 생일 기준의 만 나이**이며, 라이브러리의 출생연도 기반 세는나이를 사용하지 않는다. 끝 나이는 해당 구간 종료 직전의 만 나이다. 정확한 날짜도 함께 제공하여 나이 범위만으로 경계를 단정하지 않게 한다.
- 출생시각 모름이면 `available: false`, `reason: 'birth-time-required'`, `periods: []`이다. 알려진 분 안에 절기가 바뀌어 년주·월주가 미확정이면 `reason: 'solar-term-uncertain'`으로 계산을 보류한다. 생일의 정오나 자정을 대신 넣어 기산 나이·날짜를 만들지 않는다. 실제 입력은 분 단위이므로 초 단위 출생시각의 정확도를 주장하지 않는다.
- 각 구간에는 천간·지지·지지 본기·원국 일간과의 십성·확정된 원국과의 천간합/지지육합/지지충을 그대로 보존한다. 계산 근거에는 `daeun.direction`, `daeun.start`, `daeun.period.N` 등의 ID와 `origin: 'calculation'`을 둔다. 생활 해석은 이 자료를 읽는 서비스 설명이며 특정 사건·질병·사고·수명 날짜를 계산하지 않는다.

기산법 설명과 출처는 `method`·`sources`로 반환하여 접힌 계산 근거에서 확인한다. 현대 표준시, 태양시 미보정, 시진 단위와 분 단위 기산, 고전의 날짜 환산과 현대 달력 적용 차이로 다른 만세력과 시작 시점이 다를 수 있다. 한 방식만 유일한 정답이나 미래 예측 정확도의 증거라고 표현하지 않는다.

## 쉬운 풀이와 원자료를 읽는 순서 — 2026-11-13

각 장은 제목, 핵심을 먼저 말하는 소제목, 쉬운 상세 문단 순서로 제공한다. 첫 화면은 타고난 바탕과 연애·인연, 일·진로, 재물, 배움의 개인 풀이부터 읽게 한다. 개인 풀이에서는 전통적으로 어떻게 해석하는지, 생활에서 어떤 모습으로 나타날 수 있는지, 구체적인 가상 사례와 활용 방법을 친절한 말투로 이어 설명한다. 짧은 요약만 남기거나 명리 용어의 정의를 앞세우지 않는다. 글자의 개수를 실제 능력·재산·사건의 발생 확률로 바꾸지 않으며 모르는 출생시간과 절기 경계의 후보도 기존 계산 상태를 유지한다.

`reader-summary.mjs`는 이미 계산한 출생 일간·계절·십성·합충과 해·달의 관계를 개인 풀이에 연결한다. `report.reader`의 평생운·연간운·12개월은 문장과 주제별 본문, 실제 근거 ID, 원래 상세 단원으로 가는 연결을 제공한다. 이 문장은 서비스가 작성한 공통 의미와 생활 예시를 계산 결과에 연결한 해설이며 `service-reference`로 구분한다. 별도의 감정인이 개인의 실제 경험을 확인했다거나 새로운 미래 사건을 계산한 것처럼 표시하지 않는다. 필요한 사실 ID가 없으면 임의의 일반 풀이로 대신하지 않고 생성을 중단한다.

### 내가 어떤 사람인지 먼저 설명하는 본문

`person-portrait.mjs`는 평생운·전체 풀이의 첫 부분에 인물상과 다섯 주제(선택, 관계, 일, 부담, 의도와 다르게 보이는 모습)를 제공한다. 첫 제목은 ‘당신은 … 사람입니다’로 핵심을 말하고, 실제 생활의 반응, 장점이 부담으로 바뀌는 조건, 주제마다 다른 가상 장면과 대처를 짧은 문단으로 잇는다. 타로의 구체적인 서술 방식을 참고하되 카드의 뜻을 사주 계산으로 바꾸어 쓰지 않는다.

- 첫 인물상은 확정된 월간·일지 본기의 십성을 먼저 읽고, 같은 관계가 겹치면 다른 확정 자리로 이어 간다. 각 주제는 해당 주제와 연결한 관계를 읽는 순서로 정리한다. 이 순서는 표시 편의를 위한 서비스 규칙이며 강약·격국·용신이나 대표 성격의 순위를 계산한 결과가 아니다.
- 일간, 실제로 확인한 십성 관계, 기존 계절 관계 규칙, 모든 합·충에 연결한다. 같은 일간 한 줄로 전체 성격을 대신하지 않는다. 확인된 관계는 다른 면의 설명에도 남기며, 시간 모름이나 절기 경계에서 미확정인 자리는 새로 채우지 않는다.
- 모든 근거 ID는 기존 `report.facts`에 존재해야 한다. 일간과 실제 관계 계산도 다시 대조하며, 빠진 근거가 있으면 임의의 공통 인물상으로 대체하지 않는다. 이름·성별·선택한 운세 연도는 타고난 성격 문장을 바꾸지 않는다.
- 개별 관계의 뜻, 관계를 이어 쓴 문장과 생활 예시는 공통으로 작성한 참고 해설이다. 같은 단서에 같은 문장을 쓰며 다른 확정 단서와 조합한다. 원국마다 별도의 심리 검사나 미래 사건을 확인한 것으로 표시하지 않는다. 이 선택 방식과 문장의 성격은 접힌 ‘이 성격 풀이의 근거’와 복사문에 함께 보존한다.
- 새 본문과 다섯 주제는 먼저 펼쳐 보이고, 기존 성격·적성·인생 흐름 세 단원과 예전 요약은 ‘성격·적성의 다른 풀이’에 보존한다. 기존 18개 주제와 상세 계산·해설 전체, 목차·근거 이동·복사 기능은 유지한다. 연간·월별 상품에는 평생운의 새 본문을 섞어 넣지 않는다.

### 나의 성향을 올해·월별·10년 구간에 연결하기

`reader-summary.mjs`의 `describePersonalPeriod()`는 실제 원국에서 해당 분야의 성향을 읽고, 실제 시기의 두 십성 주제와 연결한다. 평소 행동 → 해당 시기에서 활용할 장면 → 반복하기 쉬운 부담 → 대처 순서로 쓰며, 문장에서 참조한 원국 관계 코드도 반환한다. 연간·각 달의 연애·일·재물·학업에서 이 연결을 사용한다. `daeun-reading.mjs`도 같은 규칙을 사용하되 해당 10년 구간의 사실 ID와 원국 사실 ID를 함께 보존하므로 돈·일·관계·배움에 같은 추상적인 문단을 반복하지 않는다.

시기표에서는 계산된 월운의 시작·끝 날짜와 함께 본인의 성향 때문에 놓치기 쉬운 점, 조심할 상황, 대처를 먼저 제공한다. 기회, 도움을 구할 사람의 행동, 문서·계약의 확인점도 이어서 읽는다. 표시한 기간은 전통 계산법으로 나눈 운의 구간이며 사고·질병·만남·계약 결과가 발생할 날짜가 아니다. 경고는 실제 계산에 연결한 해석과 생활 제안으로 제공하고, 발생 확률이나 위험 점수는 만들지 않는다.

성격은 ‘한눈에 보는 나’ 다섯 행 표, 시기는 실제 12개월의 기간·기회·주의를 나란히 놓은 표로 먼저 찾을 수 있다. 표의 내용은 해당 본문의 제목과 모든 기회·주의 항목을 그대로 사용하며 새 점수나 순위를 만들지 않는다. 행의 링크를 누르면 해당 상세 설명을 펼쳐 이동한다. 작은 화면에서는 같은 표의 행을 세로로 읽고, 긴 내용과 날짜를 생략하지 않는다.

개인 본문은 짧은 문단으로 모두 보여주며, 해석의 근거 링크를 누르면 해당 원자료를 펼쳐 이동한다. 전체 복사도 개인 풀이부터 시작하고 확인되지 않은 출생시각의 범위는 앞부분에 한 번 알린다. 월별운은 현재와 다음 절기월의 핵심을 먼저 보여준 뒤 해당 연도의 12개월을 모두 제공한다.

원래 계산 문장, 적용한 해석 규칙, 공통 참고 설명은 계산·해석 자료의 펼치기 영역에 모두 남긴다. 전체 계산자료와 용어 설명도 별도로 확인할 수 있으며, 복사에는 해당 상품의 쉬운 풀이와 원래 근거를 함께 포함한다. 이 변경은 화면과 설명의 개선이며 달력·십성·합충·참고표·결제 계산을 바꾸지 않는다.

### 항목별 개인 풀이와 시기표

평생운은 성격·속성·적성·인생 흐름, 연애·부모·자녀 관계, 일·직업·학업, 재물·문서, 도움을 구할 사람·주의할 관계, 생활 리듬·공간·안전·대처 방법을 나눠 읽는다. 제목과 핵심을 먼저 말하고, 여러 짧은 문단으로 생활 모습과 구체적인 가상 사례를 연결한다. 직업은 성향을 활용할 수 있는 직무 예시이며 취업 성패 판정이 아니다. 부모·자녀의 존재나 실제 가족 사건, 질병·임신·수명·사고 날짜는 계산하지 않는다. 건강 관련 글은 생활 리듬을 돌아보는 범위이고 공간 조언은 실제 방의 도면을 분석한 풍수 판정이 아니다.

`reader-extras.mjs`의 시기표는 선택한 연도의 실제 12개월 관계와 모든 합·충을 근거 ID에 남긴다. 각 달에 기회, 도움을 구해 볼 사람의 행동, 문서·계약에서 확인할 점, 주의와 대응을 구분한다. 월별운·전체 상품에서만 표시하고 복사한다. 특정 인물을 만나는 날짜, 계약하기 가장 좋은 날이나 사고 위험도를 산출하지 않는다. 합을 성공 보장으로, 충을 사고·이별의 예고로 바꾸지 않는다.

색·숫자·방향은 확정된 일간의 오행에 연결한 **전통 대응표**이며 평생운·전체에서 제공한다. 부족한 오행을 용신으로 간주하지 않는다. 색과 방향은 한국민족문화대백과사전 [「색」](https://encykorea.aks.ac.kr/Article/E0027476), 숫자는 [《역학계몽통석》 사고전서본 원문](https://zh.wikisource.org/wiki/易學啟蒙通釋_(四庫全書本)/全覽)의 하도 대응을 대조했다. 목은 청·3/8·동, 화는 적·2/7·남, 토는 황·5/10·중앙, 금은 백·4/9·서, 수는 흑·1/6·북이다. 행운 번호·유리한 방위·가구의 길한 자리로 확정하지 않으며 근거와 한계를 출처에 남긴다.

공통 안전 실천은 CPSC의 [가구 전도 방지](https://www.cpsc.gov/Safety-Education/Safety-Education-Centers/AnchorItgov?language=en)와 NHTSA의 [졸음운전 방지](https://www.nhtsa.gov/risky-driving/drowsy-driving) 자료에 근거한다. 이런 안전 수칙은 운세 예측과 구별하며 특정 사주에 위험이 더 크다는 근거로 쓰지 않는다.

### 두 사람의 궁합

`compatibility.mjs`의 `buildCompatibilityReading(chart, partnerChart)`는 기존 `makeProfile`, `getTenGod`, `interactionPairs`를 재사용해 두 사람의 확정된 일간과 모든 확정 기둥의 조합을 비교한다. 완전한 두 차트에서는 4×4의 기둥 쌍을 확인하고 실제 천간합·지지육합·지지충을 위치별로 모두 기록한다. 일지끼리의 비교와 없는 짝, 미확정으로 제외한 기둥도 구분한다. 모든 사실과 공통 해석·가상 사례의 성격을 펼쳐 확인할 수 있고 복사에도 남긴다.

#### 궁합 점수와 막대그래프

`compatibility-score.mjs`는 확인된 사주 비교 자료를 **오쭈다의 고정된 제품 규칙**으로 환산한다. 전통 문헌에 정해진 공식, 과학적으로 검증된 관계 점수나 성공 확률이라고 표시하지 않는다. 점수 계산은 브라우저 안에서 결정적으로 수행하며 이름·성별·현재 시각·난수·결제 횟수를 사용하지 않는다. 두 사람의 순서를 바꿔도 항목 점수와 종합 점수가 같다.

| 항목 | 점수 규칙 |
| --- | --- |
| 기본 성향 | 일간 오행이 같으면 80점, 상생 관계면 85점, 상극 관계면 60점. 일간끼리 천간합이 있으면 10점 추가. |
| 서로의 보완 | 확정된 글자에서 각 오행이 차지하는 비중을 구한다. 오행마다 20%보다 적은 비중을 상대가 더 가진 비중으로 얼마나 채우는지 양방향으로 계산하고, 두 비율의 평균 × 50 + 50을 반올림한다. 채우는 정도는 해당 부족분을 넘지 않으며, 기준보다 부족한 비중이 없으면 그 방향의 비율은 1이다. 20%는 수치 비교용 기준이며 용신이나 실제 필요한 오행 판정이 아니다. |
| 일상 호흡 | 두 일지가 육합이면 90점, 충이면 40점, 같은 글자면 80점, 그 밖에는 65점. |
| 관계 조화 | 확정된 모든 기둥 쌍을 비교하고 `50 + (천간합 수 × 20 + 육합 수 × 30 − 충 수 × 30) / 비교한 기둥 쌍 수`를 반올림한다. 위치가 다른 같은 짝도 원래 비교 자료대로 포함하며 전체 비교 수로 정규화한다. |
| 종합 궁합 | 위 네 정수 점수를 25%씩 반영한 평균을 반올림한다. |

점수는 0~100 범위의 정수로 표시한다. 미확정 기둥은 오행 비중·합충 비교와 분모에서 함께 제외하며 별도 감점하지 않는다. 각자 몇 글자를 확인했는지와 제외 범위도 남긴다. 각 항목은 기존 계산 근거와 `score.*` 기준 행에 연결하며 제품 규칙의 근거는 `service-reference`로 구별한다.

`compatibility-score-view.mjs`는 큰 종합 점수와 네 가로 막대를 만든다. 막대 길이·화면 숫자·접근성 meter 값은 같은 정수 점수를 사용한다. 세부 기준과 사용 범위는 펼쳐 읽고 모든 점수·설명·기준은 복사문에도 포함한다. `compatibility-app.mjs`가 기존 결제 확인 흐름 안에서 이 화면을 추가하며 입력 변경·만료·로그아웃·계정 변경 시 본문과 함께 제거한다. 새 구매나 결제 서버 변경은 필요하지 않다.

#### 띠 표시와 두 사람의 띠 관계

`zodiac.mjs`는 기존 계산 결과의 년주 지지에서 `animal`을 읽는다. 사주와 동일하게 **입춘이 바뀌는 한국 시각**을 기준으로 하며, 화면에는 ‘사주 기준 · 입춘’을 짧게 표시한다. 출생 연도를 12로 나누거나 한국 음력의 연도를 그대로 사용하지 않는다. 양력·한국 음력으로 입력한 같은 생일은 같은 띠를 보여준다. 입춘일의 시간 모름이나 입춘 교체 순간이 포함된 1분은 기존 년주의 두 후보를 모두 보존한다. 입력이 미완성이거나 잘못되면 이전 띠를 계속 보여주지 않는다.

띠 표시는 입력 화면·회원별 기기 저장 목록·결과·복사문에 반영한다. 표시값을 저장 자료나 구매 해시에 추가하지 않으며, 미리보기 계산이 실패하더라도 기존 자동저장이나 저장 목록 선택을 막지 않는다. 새로운 구매나 서버 요청은 띠 계산에 필요하지 않다.

궁합의 ‘두 사람의 띠’는 이미 비교한 **년지와 년지 사이**의 육합·충만 별도로 설명한다. 다른 기둥에서 발견한 합·충을 띠의 관계로 바꾸어 쓰지 않는다. 같은 띠, 비교한 육합·충이 없는 짝, 한쪽 년주가 미확정인 경우를 구분한다. 삼합·형·해·파·원진 또는 별도의 띠 점수를 계산했다고 표시하지 않는다. 기존 일간·일지·다른 기둥의 비교는 모두 보존하며, 띠만으로 전체 궁합을 결정하지 않는다.

확인한 자료: [한국민족문화대백과사전 「띠」](https://encykorea.aks.ac.kr/Article/E0017225)의 태어난 해 지지와 동물의 대응, [「궁합」](https://encykorea.aks.ac.kr/Article/E0006817)의 십이지를 이용하는 전통 궁합 설명, [「사주」](https://encykorea.aks.ac.kr/Article/E0025957)의 입춘 기준 년주, [6tail 공식 간지 문서](https://6tail.cn/calendar/lunar.ganzhi.html)의 `getYearInGanZhiExact()` 기준을 구분해 참고했다. 이 자료는 전통의 기준을 설명하며 실제 두 사람의 관계나 미래를 검증한 자료가 아니다.

상대의 출생 정보는 한국 음양력·시간 모름을 지원하며 브라우저 안에서만 처리한다. **궁합은 별도 20쭈** 상품이고, 평생운을 구매하지 않아도 아지트 메인의 독립 궁합 배너 또는 사주 첫 화면 메뉴로 `compatibility.html`에 들어가 두 사람의 정보를 넣어 단독으로 구매한다. 전체 사주 30쭈에는 포함하지 않는다. 같은 두 사람은 결제한 시각부터 24시간 동안 추가 차감 없이 다시 보며, 무료 재조회는 만료 시각을 늘리지 않는다. 만료 후 새로 표시된 금액으로 펼치기를 눌러야 다시 결제한다.

두 사람의 정규화된 양력 날짜·알려진 시각을 정렬하고 회원별 구분값과 별도 네임스페이스를 포함해 SHA-256 `pair_key`를 만든다. 따라서 양력·음력으로 같은 생일을 넣거나 나와 상대의 순서를 바꾸어도 같은 회원의 같은 쌍으로 구분한다. 시간이 알려진 입력과 모르는 입력은 별도 쌍이다. 원래 사주의 `chart_key`와 기존 세 상품·전체 이용권은 바꾸지 않는다. 원본 생일·시간·풀이를 서버에 보내지 않으며 결제 서버에는 해시만 보낸다. 요청한 출생 정보 저장은 아래의 회원별 기기 저장에만 적용한다.

상대 또는 본인 입력을 바꾸면 이전 궁합과 점수·복사 내용을 지운다. 만료된 본문도 화면과 복사에서 닫으며 자동 결제하지 않는다. 계정·이용 모드가 바뀌면 입력과 결과를 초기화한다. 늦게 끝난 계산은 작업 세대·현재 입력·계정·24시간 권한을 다시 확인해 화면을 복원하지 못하게 한다. 결혼·이별의 확정 예측이나 성별·가족 역할을 강제하는 판정은 제공하지 않는다.

### 읽기 편의와 근거가 있는 생활 제안

구매한 풀이를 먼저 읽을 수 있게 다른 상품 선택판은 기본 접힘으로 둔다. 현재 읽는 상품과 재조회 조건은 밖에서 확인할 수 있다. 보통·크게 글자 조절, 단원 바로가기, 월별 이동·모두 펼치기는 결제와 관계없는 읽기 기능이다. 생시나 절기 경계가 미확정이라는 중요한 안내는 원자료를 펼치기 전에도 보인다.

생활 제안은 계산 자료에서 실제로 확인한 십성과 합·충에 연결한다. 제안마다 제목, 그 제안을 한 이유, 해 볼 일, 함께 살필 점, 관련 `factIds`, `origin: 'service-advice'`를 둔다. 원자료의 인용문이나 전통의 확정 판단으로 제시하지 않고 오쭈다가 쓴 생활 제안임을 밝힌다. 같은 규칙에 같은 제안 문장이 쓰일 수 있지만 근거가 없는 달에 다른 달의 점괘를 임의로 배정하지 않는다.

12개월에 걸쳐 생활 제안의 중복 제거 상태를 공유해 뒤쪽 달의 조언이 사라지던 부분을 고친다. 각 달은 그달에 확인된 자료를 근거로 제안을 온전히 제공하며, 복사문도 해당 달의 이유와 실천 내용을 포함한다. 10년 대운은 위의 별도 계산 모듈에서 확인된 경우에만 제공하고, 계산하지 않은 용신·미래 사건은 추가하지 않는다.

## 사주 상세 풀이 이용권 — 결제 후 24시간·전체 30쭈·항목마다 10쭈

일반 회원은 **평생운·올해운·월별운을 각각 10쭈**에 구매하며, 각 항목을 결제한 시각부터 **24시간 동안** 이용한다. 같은 회원·같은 출생 정보·같은 항목·같은 연도의 유효한 이용권이 있으면 다시 열 때 0쭈다. 24시간이 지나면 해당 이용권이 만료되고, 표시된 금액으로 다시 펼치기 버튼을 눌러야 새로 결제된다. 조회·연도 선택·항목 선택·시간 경과만으로 차감하거나 자동 갱신하지 않는다. 다시 읽어도 만료 시각을 뒤로 미루지 않는다.

월별운 한 항목에는 선택한 연도의 12개월이 모두 포함되며, 이용 기간 안에는 개별 월을 열 때 다시 차감하지 않는다. 평생운은 풀이의 대상이 평생이라는 뜻이며, 이용 기간은 다른 항목과 같이 24시간이다. 평생운에는 선택 연도가 없고, 올해운·월별운의 다른 연도는 별도 항목이다.

**전체 풀이 30쭈**는 같은 출생 정보의 평생운과 선택한 연도의 올해운·월별운을 한 번에 연다. 아직 유효한 항목은 제외하여 실제 결제액은 미구매·만료 항목 수 × 10쭈다. 유효한 항목이 하나면 20쭈, 둘이면 10쭈, 셋이면 0쭈이며 전부 만료되었으면 다시 30쭈다. 제외된 항목은 원래 만료 시각을 유지한다. 전체 보기의 유효 시각은 세 항목 중 가장 이른 만료 시각이며, 이후에도 남아 있는 유효한 항목은 개별로 열 수 있다. 새로 결제한 항목만 결제 시각부터 24시간을 부여한다.

| 제품 키 | 대상 | 이용권의 연도 | 서버 가격 | 이용 시간 |
| --- | --- | --- | --- | --- |
| `lifelong` | 원국에 근거한 평생운 | `0` (`null`도 `0`으로 정규화) | 10쭈 | 결제 후 24시간 |
| `annual` | 선택 연도의 연간운 | 1900~2050 | 10쭈 | 결제 후 24시간 |
| `monthly` | 선택 연도의 12개월 월운 | 1900~2050 | 10쭈 | 결제 후 24시간 |
| `all` | 평생운 + 선택 연도 올해운 + 선택 연도 12개월 월운 | 평생운 `0`, 나머지는 선택 연도 | 최대 30쭈, 유효한 항목 제외 | 각 항목의 원래 만료 시각까지 |
| `compatibility` | 두 사람의 관계 풀이 (별도 상품) | 사용하지 않음 | 20쭈 | 결제 후 24시간 |

만료는 이용 시간이 끝난다는 뜻이다. 재결제를 이유로 같은 입력·같은 연도의 사주 계산이나 풀이를 임의로 바꾸지 않는다. 서버는 생년월일·출생시각·이름·성별·풀이 본문을 받거나 저장하지 않는다. 클라이언트가 회원별 구분값과 정규화된 양력 생일·시각으로 만든 64자리 SHA-256 `chart_key`만 출생 정보를 구별하는 데 사용한다. 해시 방식은 기존과 같으며, 시간을 모르는 입력과 시각을 아는 입력은 별도 출생 정보다. 선택 연도는 해시가 아니라 항목 이용권의 `year`로 구분한다.

### 별도 궁합 조회·결제 계약

- 조회: `saju_compatibility_status_v1(p_pair_key text default null)`.
- 구매: `saju_compatibility_buy_v1(p_request_id uuid, p_pair_key text, p_expected_user uuid, p_expected_charge integer, p_verify_only boolean default false)`.
- `access_version:1`, `entitlement_version:1`, `access_hours:24`를 유지한다. 현재 판매가는 `price:20`, 신규 결제·재조회 차감은 `charged:20|0`이다. 과거 10쭈 영수증은 `price:10`, 무료 재조회는 `charged:0`으로 받는다. 기존 사주 v4의 계약이나 이용권은 변경하지 않는다.
- 같은 회원의 같은 두 사람은 순서와 양력·음력 입력 방식에 관계없이 정규화한 해시로 확인한다. 유효한 이용권은 추가 결제 없이 조회하며 만료 시각은 그대로 유지한다.
- 응답을 잃은 같은 요청은 같은 UUID로 복구한다. 만료된 UUID는 `access_expired`로 중단하고, 사용자가 바뀐 가격을 확인해 다시 눌렀을 때만 새 요청으로 구매한다. 표시 금액이 0쭈 또는 이전 가격 10쭈였으면 20쭈로 올려서 자동 결제하지 않는다.
- 서버는 비공개 `compatibility_entitlements`와 `kind:'saju_compatibility_v1'`인 실제 지출을 함께 검증한다. 신규 가격은 20쭈이며, 기존 10쭈 거래와 아직 유효한 이용권도 원래 결제 금액·만료 시각을 보존한다. 조회의 `price`는 현재 가격 20이고 각 영수증의 `price`는 실제 결제한 10 또는 20이다. 재조회와 `verify_only`는 원장을 쓰거나 이용 시간을 연장하지 않는다. 관리자 구매 내역에는 ‘궁합’으로 표시한다.

### v4 조회·결제 계약

- 조회: `saju_reading_status_v4(p_chart_key text default null)`. `null`은 잔고·가격·이용 시간만 조회하며 출생 정보별 이용권을 나열하지 않는다.
- 개별 구매: `saju_reading_buy_v4(p_request_id uuid, p_chart_key text, p_topic text, p_year integer, p_expected_user uuid, p_expected_charge integer, p_verify_only boolean default false)`.
- 전체 구매: `saju_reading_buy_all_v4(p_request_id uuid, p_chart_key text, p_year integer, p_expected_user uuid, p_expected_charge integer, p_verify_only boolean default false)`.
- 조회와 성공 영수증은 `access_version:4`, `access_hours:24`, 서버 기준 시각 `server_now`를 제공한다. 각 개별 이용권·기존 v1 이용권·성공 영수증에는 `paid_at`, `expires_at`를 제공한다. 개별 만료는 `paid_at + 24시간`이며, 전체 영수증의 `expires_at`는 세 항목 만료 중 최솟값이다.
- 개별 성공 영수증은 기존 `entitlement_version:2`와 `price:10`, `charged:10|0` 형식을 유지한다. 전체는 `entitlement_version:3`, `price:30`, `charged:0|10|20|30`과 검증된 세 개별 영수증 `items`를 제공한다. 두 형식 모두 회원·해시·항목·연도·요청 UUID·잔고·재사용 여부를 검증한다.
- 조회 성공은 현재 `coins`, `prices:{lifelong:10,annual:10,monthly:10,all:30}`와 **아직 유효한** `entitlements:[{topic,year,request_id,paid_at,expires_at,price}]`를 반환한다. 기존 v1 전체 이용권도 유효할 때만 `bundle_entitlement:{request_id,paid_at,expires_at,price}`로 반환한다. 해당 이용권이 없으면 빈 배열과 `null`이다. 전체 구매 내역은 세 개별 이용권으로 조회된다.
- `p_expected_charge`에는 버튼을 누르기 직전 표시된 금액을 보낸다. 새 요청의 서버 계산액이 달라졌으면 `reason:'price_changed'`와 `required`를 반환하고 차감하지 않는다. 화면이 새 금액을 표시한 뒤 다시 누르게 한다. 오래된 0쭈 화면으로 만료 뒤 10쭈를 조용히 차감하지 않는다.
- 확인 전용 요청은 유효한 기존 영수증만 반환하고, 잔액·원장·이용권·전체 확인 기록을 쓰지 않는다. 유효한 이용권이 없으면 `not_found`이며, 이미 사용된 만료 요청 UUID이면 `access_expired`다. 세 항목이 모두 유효하더라도 연결된 최신 전체 확인 기록이 없으면 `not_found`, `required:0`이며, 실제 전체 열기에서는 0쭈 확인 기록을 만들 수 있다.

구매 함수는 로그인·기대 계정·실제 회원·정지·지갑·잔고를 확인한다. `p_expected_user`가 서버의 `auth.uid()`와 다르면 `account_changed`로 중단한다. 전송 중 다른 탭에서 계정이 바뀌어 SDK가 새 계정의 토큰을 사용하더라도 새 계정에 과금하지 않는다.

### 만료·재구매·재시도

서버는 요청 UUID 잠금, 지갑 행 잠금 순서로 처리한다. 잠금을 얻은 뒤 읽은 서버 시각으로 만료를 판단하며 `expires_at > server_now`일 때만 유효하다. 정확히 만료 시각에 도달하면 재구매가 필요하다. 무료 재조회는 구매 시각이나 만료 시각을 갱신하지 않는다.

성공한 요청 UUID의 유효한 재시도는 0쭈로 원래 영수증을 반환한다. 요청이 만료되었거나 이후 새 구매로 교체되었으면 같은 UUID로 다시 차감하지 않고 `access_expired`로 중단한다. 클라이언트는 이 오류를 새 유료 호출로 자동 재시도하지 않는다. 사용자가 새로 표시된 금액을 확인하고 다시 누를 때 새 UUID로 구매한다. 네트워크 응답을 잃은 경우에는 동일 요청으로 확인하여 중복 결제를 막는다. 다른 회원·출생 정보·항목·연도에 사용한 UUID는 `request_conflict`다.

만료된 결제 원장을 삭제하거나 금액을 고치지 않는다. 재구매할 때 새 지출 기록을 추가하고, `(user_id,chart_key,topic,year)`의 현재 이용권 포인터와 구매 시각만 갱신한다. 기존 및 새 지출은 항목별 `kind:'saju_reading_v2'`, 사주 항목 제목·연도로 기록한다. 계정을 삭제하면 외래키에 따라 해당 계정의 이용권도 함께 정리된다.

화면은 서버에서 확인한 남은 시간으로 이용권을 판단한다. 열어 둔 풀이도 만료되면 본문과 복사 기능을 닫고 다시 결제할 금액을 표시한다. 탭 복귀·페이지 복원·복사 등에서도 만료를 확인한다. 이 기능은 정상 화면과 서버 결제의 이용 시간을 제어한다. 이미 복사하거나 저장한 풀이를 회수하는 기능은 아니며, 사주 계산·자료는 기존처럼 브라우저에서 처리한다.

### 전체 구매의 원자적 처리

전체 구매는 한 트랜잭션에서 세 항목의 유효 상태와 필요 금액을 확인한다. 잔고가 충분할 때만 한 번 차감하고 만료·미구매 항목을 갱신한다. 잔고 부족·중간 실패로 일부만 결제된 상태를 남기지 않는다. 전체를 구매한 뒤 유효한 세부 항목을 따로 열면 추가 차감하지 않는다.

전체 요청 UUID는 기존과 같이 `kind:'saju_reading_all_v3'`, `coins:0`인 묶음 확인 기록으로 예약한다. 실제 지출은 새로 구매한 항목별 10쭈 기록에만 남긴다. 비공개 `all_orders`는 최신 전체 요청·연도·원래 차감액·세 항목 영수증을 연결하며, 새 거래로 바뀌어도 이전 원장은 보존한다. 조회·복구에서는 각 항목의 실제 결제 영수증, 회원·해시·항목·연도, 유효 시간을 다시 검증한다.

클라이언트는 평생운 0년·올해운 선택 연도·월별운 선택 연도의 세 항목이 모두 유효하고 잔고·합산 금액·만료 시각도 맞아야 전체 본문과 복사를 연다. 전체 본문은 기존 설명·12개월·조언·전체 계산자료를 보존하며 공통 근거와 출처를 한 번씩 정리한다.

### 기존 이용권과 오래된 클라이언트

이미 구매한 v1·v2·v3 이용권에도 **원래 결제 시각부터 24시간**을 적용한다. 과거 구매 시각을 배포 시각으로 바꾸거나 배포만으로 무료 이용 기간을 추가하지 않는다. 유효한 v1 전체 이용권은 기존 대상 범위에서 0쭈로 재열 수 있으며 `legacy_bundle:true`로 반환한다. 이 이용권도 만료되면 새 정책의 개별 10쭈·전체 최대 30쭈로 명시적으로 재구매한다. 과거의 10쭈 v1 전체 이용권을 새로 만들지 않는다.

기존 public v1·v2·v3 구매·조회 경로를 차단한다. v1 구매 함수는 실행 권한을 회수한 상태를 유지하고, 호출 가능한 구버전 RPC는 `update_required`로 중단한다. 내부 구버전 구매·조회 함수의 회원 실행 권한도 회수한다. 24시간 조건을 모르는 오래된 화면이 구버전 경로로 결제하거나 무기한 권한을 다시 얻지 못하게 한다. 과거 영수증 조립 함수는 비공개 검증 용도로만 유지한다. 이미 적용된 마이그레이션은 수정하지 않으며 v4 변경은 새 마이그레이션으로 추가한다.

테이블은 비공개 `ojjuda_saju_internal` 스키마에 있고 RLS를 켰다. 외부 회원에게 테이블 직접 접근이나 영수증 조립 권한을 주지 않는다. 내부 구매·조회 함수만 제한된 `SECURITY DEFINER`를 쓰고, 공개 RPC는 `SECURITY INVOKER`, 모든 함수는 빈 `search_path`를 사용한다. 확인된 관리자 미리보기는 기존 관리자 확인 흐름에서 결제 호출을 생략한다.

```sh
npm --prefix tests run test:saju
```

결제 검증은 PGlite 임시 데이터베이스의 가상 회원과 지갑만 사용한다. 기존 마이그레이션에서 최신 마이그레이션으로 업그레이드하여 가격·권한·원장·만료·재구매·재시도·오래된 금액의 결제 차단을 확인한다. 화면과 결제 클라이언트는 별도 가상 환경에서 확인하며 실제 회원에게 쭈를 차감하지 않는다. 단일 PGlite 연결의 재시도 검증을 실제 다중 연결 부하 시험으로 표현하지 않는다.

### 이름·성별과 저장한 사람 — 2026-11-13

사용자의 추가 요청에 따라 이름·성별·생일·양력/음력·윤달·출생시각을 `saved-profiles.mjs`로 이 기기의 `localStorage`에 저장한다. 원본 개인정보는 서버로 전송하지 않는다. 이름은 최대 30자의 표시용 문자열이고 성명학 계산에는 사용하지 않는다. 성별은 `male`·`female`·미선택을 구분하며 실제 대운 계산에만 사용한다. 성별을 관계 역할·능력·길흉으로 확대하지 않는다.

저장 키는 검증한 로그인 회원 UUID를 기준으로 나누며 익명 회원의 저장은 허용하지 않는다. 목록은 최대 20명이고 자동으로 오래된 사람을 지우지 않는다. 같은 정보는 중복 저장하지 않고 선택한 사람의 정보는 수정할 수 있다. 저장 공간 부족·접근 제한·잘못된 JSON을 성공이나 빈 목록으로 조용히 덮지 않는다. 입력을 바꾸거나 계정을 전환한 뒤 늦게 끝난 검증으로 이전 정보를 저장하지 않도록 검사한다.

`profile-picker.mjs`는 입력창 위에 이름·성별·생일·시간과 저장 인원을 표시하고 모든 문자열을 `textContent`로 렌더링한다. 출생 정보 필드의 실제 입력·변경 후 600ms 동안 추가 입력이 없으면 유효한 내용을 자동 저장한다. 미완성 생일과 한글 조합 중에는 기다리고, 필드에서 벗어나거나 페이지가 숨겨지기 전에는 완성된 예약 입력을 동기식으로 저장한다. ‘지금 저장’ 버튼과 유효한 정보로 ‘풀이 펼치기’를 누를 때의 저장도 유지한다.

저장 목록은 `payment.js`에서 확인한 회원 신원에 연결하며 잔액 조회의 성공을 기다리지 않는다. 최초 로그인 확인 전에 직접 입력한 내용은 확인 후 저장하되, 실제 계정 변경·로그아웃·삭제·새 사람 입력·다른 사람 선택은 이전 예약을 취소한다. 목록 갱신·화면 복귀·선택만으로 저장하지 않으며, 삭제된 ID를 새 사람으로 되살리지 않는다. 저장 실패는 화면에 알리되 이미 준비한 유료 풀이를 막거나 추가 차감을 일으키지 않는다. 사주와 궁합 두 입력창은 같은 회원의 저장 목록을 공유한다. 자동저장·선택·수정·삭제는 구매를 실행하거나 이용권·결제 기록을 변경하지 않는다.

저장한 사람에는 24시간 만료를 적용하지 않는다. 로그아웃·계정 변경 시 화면의 이전 입력과 목록을 지우고 현재 회원의 목록만 불러온다. 다른 기기나 브라우저로 자동 동기화하지 않으며 브라우저 저장 데이터를 지우면 목록도 지워진다. 기존 `chart_key`·`pair_key`에는 이름·성별을 추가하지 않으므로 이름·성별만 고친 뒤 유효한 같은 출생 정보로 다시 열면 추가 차감하지 않는다.

### 목록에서 한 항목씩 읽기 — 2026-11-13

`report-view.mjs`의 ‘읽을 내용’ 목록과 이전·다음 버튼은 구매한 풀이의 한 항목만 보여준다. 처음에는 성격 요약, 올해 요약 또는 해당 월 요약을 보여주며, 성격·관계·재물·가족 등 세부 주제를 따로 고를 수 있다. 월별운은 12개월 요약을 먼저 나열하고 각 달 안에서 분야를 고르게 한다. 10년 흐름도 구간 목록에서 기간과 세부 분야로 들어간다.

선택하지 않은 원문에는 `hidden`을 적용하며 계산·해석·예시·복사할 내용은 삭제하거나 축약하지 않는다. 기존 목차·요약표·근거 링크는 이동할 대상의 항목을 먼저 표시하고 필요한 접힌 영역을 연다. 목록에는 현재 구매하여 렌더링한 상품만 들어가며, 목록 이동은 결제·이용 시간·원래 계산 결과를 바꾸지 않는다.

### 대운의 상황별 풀이 보강 — 2026-11-13

각 10년 구간의 네 기본 분야에 `daeun-situations.mjs`의 문서·계약과 사람 관계 안내를 더한다. 실제 구간에서 계산한 두 십성 관계에 해당하는 작성 규칙만 선택하며, 원국에 같은 관계가 있는지와 확인된 합·충을 연결한다. 문서는 책임·재물, 사람 관계는 배움·협력에 가까운 관계를 먼저 설명하는 편집 순서를 사용한다. 이 순서는 전통적 길흉 점수나 관계의 세기를 계산한 결과가 아니다. 안내마다 사용한 규칙과 모든 실제 계산 근거 ID를 남긴다.

앞 구간과 새 구간의 관계 코드를 비교하여 이어지는 주제와 새로 나타나는 주제를 설명한다. 비교한 앞 구간의 계산 근거도 해당 구간에 함께 남긴다. 어린 시기에 해당하는 구간의 예시는 학교·배움·공동 약속의 상황으로 제시하며 실제 가족·직업·계약 이력을 추측하지 않는다. 어떤 사람을 만나는 날짜나 문서의 성공 여부를 예측하지 않고, 제안받은 조건과 상대의 실제 행동을 살피는 구체적인 방법을 제공한다.

새 출생 정보의 과금은 기존 v4 서버 이용권을 그대로 사용한다. 개별 풀이 총액 10쭈·전체 30쭈이며 별도의 생일 추가금을 중복 부과하지 않는다. 다른 출생 정보를 열고 돌아와도 기존 이용권은 원래 결제 시각부터 24시간을 유지한다. 기기 저장 목록을 수정하거나 삭제한 사실은 할인·새 과금·만료 연장의 근거로 사용하지 않는다.

### 기회·주의·대처의 서로 다른 생활 장면

`reader-situations.mjs`는 실제로 확인된 10개 관계마다 기회를 살필 상황, 멈춰 확인할 상황, 행동을 시작하거나 바꿀 상황을 구분한 30개 작성 규칙을 제공한다. 첫 관계는 사례를, 두 번째 관계는 추가 조건을 고르며 실제 원국의 관계는 반응과 행동의 조정에 연결한다. 실제 합·충을 함께 확인하고 사용한 규칙 ID를 카드에 남긴다. 일·재물 카드의 긴 공통 문단을 다시 붙이지 않으며, 별도 상황의 핵심·조건·예시·대처로 설명한다. 같은 계산 단서에 임의로 다른 문장을 배정하지 않고, 작성한 규칙을 별개의 계산 사실이나 수많은 독립 감정으로 홍보하지 않는다.
