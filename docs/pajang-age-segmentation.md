# 파장 연령별 이용 단계 교체

## 1단계 — 연령 판별 기반 (이번 변경)
- 기존 회원가입은 만 14세 이상을 지원하며, 별도 가입 절차를 새로 만들지 않는다.
- 서버의 본인 인증 정보 `ojjuda_account_internal.member_identity.birth_date`만 사용하여 `public.pajang_age_group()`가 `adult`(만 19세 이상), `teen`(만 14~18세), `blocked`(미확인·제한 회원)을 반환한다.
- 생일이 지나면 서울 날짜 기준으로 자동 변경한다. 이용자가 직접 적은 나이, 수정 가능한 프로필, JWT 사용자 메타데이터를 판정 근거로 사용하지 않는다.
- **이번 단계에서는 기존 19세 이상 파장 입장 제한, 질문·답변, 채팅, 교환, 위치, 회원 데이터, 화면 문구를 절대로 변경하지 않는다.**
- 새로운 RPC는 본인의 등급만 알려 주며 다른 사람의 나이·생년월일은 공개하지 않는다.
- 테스트: 만 13/14/18/19/65세 경계, 생일 전날, 미확인, 익명, 정지 회원, 익명 역할의 실행 권한.

## 다음 단계 — 반드시 순서대로 진행
2. 모든 읽기·쓰기 RPC와 저장소 정책에 연령대별 서버 차단을 적용하고 14~18세/성인 데이터가 교차 노출되지 않는 회귀 검사를 추가한다.
3. 청소년에게 별도 공개형 질문·답변만 제공한다. 성인 매칭, 신호, 채팅, 위치 레이더, 프로필/사진 교환은 계속 차단한다.
4. 신고·차단·모더레이션·개인정보 노출 방지·약관·앱 등급을 검증한 뒤 청소년 기능을 활성화한다.
5. 구글 플레이 심사 기준(랜덤채팅·소개팅 핵심 기능 여부)을 확인하고 점진 배포한다.

## 배포 원칙
기존 `pajang_member` 및 교환 API를 청소년에게 열지 않는다. 이번 마이그레이션은 독립적인 판별 RPC 추가만 수행한다. 단계별 테스트를 통과하기 전에는 청소년에게 파장을 공개하지 않는다.

## 2단계 — 기존 성인 API 서버 차단 (코드 준비)
- `pajang_member`의 기존 나이 검사를 회원 인증의 `adult` 등급 검사로 강화한다. 생일·나이 미확인 계정도 차단한다.
- `pajang_private.exchange_actor`에 동일 검사를 추가해 교환 프로필과 사진, 동의 상태를 보호한다.
- `pajang_private.require_signal_member`를 강화해 신호·구매·지갑 호출 경로를 보호한다.
- 기존 저장소 정책의 `pajang_art_allowed`도 동일한 성인 기준을 사용한다.
- 기존 공개형 답변/발견 조회는 `pajang_member('entry')`를 거치므로 청소년에게 성인 콘텐츠가 노출되지 않는다.
- SQL 마이그레이션은 기존 함수 본문을 정확히 확인한 후 일치하는 부분만 변경하며 다른 경우 실패한다. 운영 DB에서 트랜잭션 롤백 시험으로 변경 예상 지점을 확인했다.
- **아직 청소년 서비스는 열지 않는다.** 성인 기능, 게시물, 기존 저장 데이터, 질문 화면은 그대로 둔다.

## 3단계 준비 — 청소년 공개 답변 시스템
- 청소년은 1:1 채팅·교환·위치·신호·결제를 사용할 수 없다.
- 청소년 전용의 질문 배포, 게시 검토와 공개 범위, 신고·차단 API를 별도 설계한다.
- 성인 프로필/답변 테이블에 청소년 데이터를 혼합하지 않는다.
