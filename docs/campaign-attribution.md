# 홍보 글별 가입 측정

## 링크와 적용 범위

게시 전에 한 글에 고유한 `utm_content`를 정한다. 실제 플랫폼 게시 URL/ID와 이 코드는 홍보 운영대장에 대응시킨다. 예:

`https://ojjuda.kr/games/onecard/index.html?utm_source=threads&utm_medium=social&utm_campaign=onecard-20261121&utm_content=threads-onecard-20261121`

- 채널: `threads`, `naver`, `instagram`, `facebook`, `youtube`, `tiktok`, `kakao`, `x`, `google`, `other`
- 매체: `social`, `blog`, `video`, `search`, `referral`, `organic`, `paid`, `other`
- 캠페인·게시글: 소문자 영문으로 시작하는 1~64자 영문·숫자·`_`·`-`. 사람 이름·연락처·사용자 ID·주소를 넣지 않는다.
- `utm_source`, `utm_campaign`은 필수다. 매체 누락은 `other`, 글 코드 누락은 `unlabeled`로 분리한다. 잘못된 값·중복 파라미터는 수집하지 않는다.
- 첫 화면, 아지트·오락실·공원, 파장 입구/메인, 원카드 독립 화면, 사주·타로·바이오리듬에 적용한다. 다른 새 랜딩에는 같은 공통 스크립트를 추가한 후 검증한다.
- `/park/` 기존 주소는 허용된 캠페인 태그를 공원 본 화면으로 넘긴다. 같은 출처 내 가입 이동은 탭 저장소를 사용하며, 추천인 `ref` 링크는 별도로 유지한다.

## 집계의 의미

운영 관리 → 방문·이용 통계 → **홍보 글별 가입**에서 확인한다. RPC는 `admin_campaign_signup_stats()`이며 관리자만 최근 30일 유입 코호트의 합계와 상위 100개 글을 조회할 수 있다. 행이 100개를 넘으면 표 제한을 표시하고 요약 수치는 전체 합계를 유지한다.

1. **홍보 링크 방문:** 비회원이 같은 탭에서 연 유효한 캠페인 한 건. 동일 태그는 24시간 안에 다시 열어도 한 번, 다른 유효한 홍보 글을 열면 새 유입이다. 직접·내부 이동은 기존 태그를 덮어쓰지 않는다.
2. **가입 화면 시작:** 그 유입에서 가입 화면을 연 횟수이며 유입별 한 번이다. 실패·취소한 가입도 시작에는 포함된다.
3. **가입 확인 완료:** 이후 실제 새 Auth 계정이 만들어지고 7일 안에 이메일 확인이 완료된 계정 수다. 브라우저의 성공 메시지를 믿지 않고 Auth 행 생성·확인 상태로 집계한다. 기존 회원 로그인, 기존 계정의 메타데이터 변경, 중복 호출, 가짜 중복가입 응답은 신규 가입으로 세지 않는다.

세 지표는 **유입된 날짜**에 연결된다. 이메일을 다음 날 확인하면 원래 유입 코호트의 완료 수가 증가한다. 여러 실제 계정이 같은 탭에서 가입할 수 있으므로 완료 계정 수가 방문·시작 수보다 클 수 있다. 사람 수·현재 회원 총계와 같지 않으며 단순히 나눠 확정 전환율로 표시하지 않는다.

신규 배포 이후의 유효한 태그만 측정한다. 과거 무태그 게시물, DNT/GPC, 차단된 저장소, 다른 기기·탭, 만료된 연결, 측정 실패는 미연결이다. 숫자 0을 '홍보 효과 없음'으로 단정하지 않는다.

## 개인정보와 안정성

- 브라우저는 허용된 코드 4개, 단기 임의 UUID와 단계만 보낸다. 원래 URL/리퍼러/연락처/IP/계정 ID를 보내지 않는다.
- 탭 임의 번호와 서버 중복 확인 값은 24시간이다. 확인용 계정 해시는 서버 비밀값을 섞고 7일 만료한다. 개인별 페이지 이동 기록과 외부 전송은 없다.
- `campaign_visit_token`은 Auth `users`/`identities` 저장 전 제거한다. 가입 확인용 값은 외부에서 읽을 수 없는 스키마에만 있고 보고에는 포함하지 않는다.
- 익명 요청은 쓰기 전용 RPC로 제한한다. 테이블 RLS·권한 차단, 출처/라벨 검증, 시간당 상한, 중복 방지를 적용한다. 로그인한 요청은 수집하지 않아 관리자도 제외된다.
- 만료 정보는 즉시 사용하지 않으며 `ojjuda-campaign-insights-retention`이 10분마다 삭제한다. 합계는 400일, 요청 제한 기록은 2일 보관한다. 배포자는 `pg_cron`과 해당 작업이 생성되었는지 확인한다.
- 가입 요청을 최대 800ms까지만 기다리게 하고 실패 시 측정 없이 기존 가입을 진행한다. 서버 측 측정 오류도 인증 트랜잭션의 실패로 전파하지 않는다. 기존 가입 자격·추천인·개인정보 검증 오류는 그대로 적용한다.
- 기존 `record_site_usage`와 `admin_site_usage_stats`는 변경하지 않는다. 새 통계를 못 읽어도 기존 통계는 표시한다.

## 검증

`cd tests && node campaign-attribution-db.test.cjs && node campaign-attribution-client.test.cjs && node campaign-attribution-ui.test.cjs && node site-usage-db.test.cjs && node site-usage-ui.test.cjs`

브라우저 검증은 CI의 설치된 Chromium에서 실행한다. 로컬 DB·클라이언트 검증은 앞의 두 명령으로 별도 실행할 수 있다.

로컬 픽스처에서 실제 이메일 확인 전후·중복·동시 단계·권한·보관·측정 장애·기존 계정 주입·추천인 정보 보존을 검증한다. 실서비스 계정을 테스트 목적으로 생성하거나 운영 집계에 테스트 이벤트를 넣지 않는다.
