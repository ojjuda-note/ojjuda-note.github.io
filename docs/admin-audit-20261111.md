# 오쭈다 아지트 관리자모드 점검 — 2026-11-11

## 관리자 메뉴 사용성 개편

- 실제 관리자 화면은 **운영 현황 / 회원·ZU / 콘텐츠 관리 / 신고·안전 / 운영·보관** 5개 작업별 묶음으로 재편했다.
- 기존 7개 내부 영역과 28개 관리 화면의 식별자·이동 주소는 유지한다. 특히 `계정 → 가입자`와 `ZU → 사용자별 ZU`처럼 같은 탭 ID를 쓰는 기능은 원래 영역을 함께 전달해 구분한다.
- 넓은 화면은 왼쪽 고정 메뉴와 오른쪽 작업 화면, 좁은 화면은 펼치는 메뉴를 사용한다. 메뉴 검색과 즐겨찾기(최대 6개)는 관리자 작업 화면을 초기화하지 않는다.
- 신고·문의·오류 건수는 기존 관리자 요약 수치에서 읽어 메뉴에 표시한다. 새 통계 테이블이나 사용자 행동 기록은 만들지 않는다.
- 기존 카드·쪽지·사진 검토의 미저장 변경 보호, 예전 `?admin=` 진입 주소, 관리자 접근 권한은 변경하지 않는다.
- `admin/navigation.js` 또는 스타일 로드가 실패하면 기존 관리자 탭 UI가 작동하도록 대체 경로를 남겼다.


## 기능 정리 결과

| 분류 | 기존 관리자 기능 | 조치 |
| --- | --- | --- |

| 콘텐츠 | 카드, 쪽지 관리, 그룹 관리, 포토땅따먹기, 위험 신호, 위치 지도, 보상 관리 | 유지. 각각 실제 콘텐츠·운영 기능과 연결되어 있음 |
| 휴지통 | 전체, 탈퇴 계정, 삭제 카드, 삭제 쪽지, 기타 보관 | 유지. 운영 복구·감사와 연결되므로 기록 임의 삭제 금지 |
| 신고·문의 | 신고, 문의·의견, 카드 이용 제한 | 유지. 모니터링·접수·제한에 필요 |
| ZU | 무료 충전, 사용자별 ZU | 유지. 재화 기능과 연결되어 있음 |

| 구형 통계 | 비회원 일별·월별 방문 | 필요할 때만 펼치는 기록으로 보존 |
| 불필요한 상세 표 | 두 게임 도전·공유 표 | 관리자 화면·조회 요청에서 제거. 과거 데이터는 보존 |

**삭제 판단:** 실제 관리자 메뉴의 6개 영역과 연결된 기능 중 안전하게 삭제 가능하다고 입증된 메뉴는 없었다. 불필요하다고 지목된 **게임 도전·공유 상세 UI는 제거**했다. 데이터·이력·마이그레이션의 임의 삭제는 진행하지 않았다.

## 새 통계의 범위

- 날짜별 방문: 최근 30일, 한국 시간(Asia/Seoul).
- 시간별 방문: 오늘의 0~23시.
- 요일별 방문: 최근 30일의 월~일 합계.
- 인기 기능: 최근 30일 아지트·오락실·공원·설정·콘텐츠/게임 선택 상위 12개.
- 비회원 인기 게임: 최근 30일 비로그인 방문에서 선택된 게임 상위 12개.
- 비회원 인기 게시판: 최근 30일 공원 카드, 그룹, 팬페이지, 인증맛집 진입 선택 상위 4개.
- 아지트 상세: 방문 도장, 오늘의 미션, 추천게임, 그룹, 축제 일정, 인증맛집, 팬페이지 선택.
- 오락실 상세: 개별 게임 선택(23개 게임 및 기타 게임) 순위.
- 유입 경로: 최근 30일 직접 방문, 네이버, 구글, 기타 검색, SNS, 외부, 사이트 내부, 캠페인.
- 숫자의 의미: 브라우저 기준 하루 1회 방문 / 기능별 하루 1회 선택. 사람 수, 순수 클릭 수, 조회수와 같지 않음.
- 비회원 구분은 클라이언트가 신고한 값이 아니라 서버의 `auth.uid() is null`로 판단한다. 게시판 통계는 **진입 선택**이며 실제 게시물 작성 수를 뜻하지 않는다.
- 통계는 신규 배포 이후부터 쌓인다. 이전에 시간·유입 경로를 수집하지 않았으므로 과거 데이터를 추정하여 채우지 않는다.
- 상세 아지트·오락실 항목은 별도 상세 집계 적용 이후부터 쌓인다. 과거의 상위 메뉴 방문 수를 세부 항목에 임의 배분하지 않는다.

## 보안·성능·사용성

- 새 저장소는 비공개 PostgreSQL 스키마 및 RLS로 보호하고, 관리자 통계 함수는 관리자 여부를 확인한다.
- 비회원 기능 집계 역시 개인 기록 없이 날짜·기능·횟수만 저장하며 회원의 게임·게시판 선택을 비회원 통계에 더하지 않는다.
- 개별 방문 URL, 방문자 IP, 리퍼러 전체 주소, 계정 ID는 저장하지 않는다. 브라우저 UUID는 매일 소금값으로 해싱한 후 중복 방지에만 사용하며 짧은 기간 후 폐기한다.
- Do Not Track / Global Privacy Control을 존중한다. 봇 유입을 일부 제외하고 전역 시간당 요청 제한을 적용한다.
- 모든 그래프를 하나의 관리 RPC로 조회하며 별도 차트 라이브러리를 추가하지 않는다. 관리자 요약 화면에서는 전체 그래프 RPC를 생략한다.
- 관리자 요약 화면에 중복 게재되던 비회원 방문 카드와 해당 조회 요청을 제거했다. 데이터는 ‘계정 → 방문 통계’에서만 확인한다.
- 2열 넓은 화면, 1열 좁은 화면. 날짜별 그래프는 넓게 배치하고 휴대폰에서는 그래프 내부만 좌우 스크롤한다. 키보드 접근을 허용한다. 아지트·오락실 상세와 비회원 인기 그래프를 포함해 총 9개.
- 조회 실패·기록 없음·로딩 상태를 나누며, 조회 실패로 기존 방문 통계가 사라지지 않게 한다.

## 검증 및 남은 조치

- SQL 회귀: 집계 정확성, 한국 시간, 중복 방지, 관리자 권한, 비공개 스키마 권한 테스트.
- DOM 회귀: 추적, 개인정보 설정, 그래프 구성, 로딩/오류, 로그아웃 시 관리자 데이터 정리.
- 화면 회귀: 360px / 768px / 1280px Playwright 테스트(자동화 CI).
- Supabase 기존 보안 검사에서 다른 프로젝트 영역(`ojjuda_note.public_cards`의 `security_definer_view`)에 대한 오류, 유출 비밀번호 탐지 비활성 경고가 확인되었다. 기존 카드 공개 정책·인증 동작의 변경은 파급 가능성이 있어 별도 영향 분석 후 처리해야 한다. 이번 통계 기능의 권한과는 구분한다.
